# hci

`index.md` は、middy の UI/UX を検討するときに当たるべき HCI の知見の索引である。所有者の判断は #274。`docs/design/ux-principles.md` の 10 原則の **根拠を深め、誤用を正し、足りないものを足す** ための層で、原則そのものを置き換えない。項目は「どの判断を助けるか」で分け、分野（知覚・記憶・…）では分けない。

## 使い方

1. 決めようとしていることを 1 行で言う（例: 「再生中に、鳴っているコードの理由の文を出すか」「固定中かどうかをどう見せるか」）。
2. `index.md` の節の見出し（何を同時に見せるか／時間で変わる情報／状態とモード／操作の対象と手がかり／選択と既定値／待ちと応答／学習の負荷／色とコントラスト／支援技術）から当たりをつけ、各項目の「当たるべき場面」で絞る。
3. 見つかったら「判断の問い」を自分の案に当て、答えを PR の「原則の点検」（ux-principles.md 5 章の 4）に 1〜2 行で書く。項目名を書けば、根拠は索引を引けば分かる。
4. **数値（秒、文字数、px、比）を根拠に使うときは、その項目の一次情報を開いてから使う。** 「確からしさ」の欄に「再現性に議論がある」「実務の経験則」とあるものは、数値ではなく向き（大きいほど／短いほど）だけを使う。開けなければ、開けなかったことを PR か Issue に書き、推測で数値を書かない。
5. 「よくある誤用」に自分の案が当たっていないか見る（7±2 を項目数の上限にする、Hick の法則で「選択肢を減らせ」と言う、APCA で WCAG 2.2 を置き換える、など）。
6. 見つからなければ、そう書いて進める。索引に足すべき知見だと思ったら、`index.md` に項目を足す PR を別に出す（今の作業に混ぜない）。

## 索引に書くもの・書かないもの

- 書く: 名前、一次情報（著者・年・題・合法に読める URL）、何を言っているか（自分の言葉で 2〜4 行）、確からしさ（実験の積み重ね／再現性に議論／実務の経験則／規範、とよくある誤用）、当たるべき場面、判断の問い、適切・不適切な例、middy との接点、確認日。
- 書かない: 本や論文の文章の引用、図表の写し、一次情報を開かずに書いた中身、違法なアップロードへのリンク。
- 確認日は、一次情報か権威ある公開資料（著者の公開版、W3C、NN/g 等）を実際に開いて確かめた日。何を開いたかを欄に書く。原論文が開けず解説だけで確かめたものは、そう書く。開けなかった項目は「未確認（理由）」とし、次の session で開けたら更新する。
- 「外したもの」の節に、検討して外した知見と理由（陳腐化、再現性が弱い、middy に関係が薄い、既存の原則と重複）を残す。再び提案されたときに同じ検討を繰り返さないため。

## 置き場所の分担

- この索引は、開発の session で AI が引くためのもの。プロダクトの文書（`docs/`）には入れず、`docs/design/ux-principles.md` の根拠欄は項目名で指すにとどめる（`standards` と同じ分担）。
- 人間が読む学習ログは GitHub Wiki に置いてよい（所有者の判断）。AI は開発の session では Wiki を読まない。
- 結果の画面の検討など、個別の課題への当てはめは、索引ではなく企画 Issue に書く。索引は課題をまたいで使える形だけを持つ。
