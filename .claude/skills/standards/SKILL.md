# standards

`index.md` は、middy の機能を検討するときに出会いうる業界標準の索引である。所有者の判断は #213。

## 使い方

1. 決めようとしていることを 1 行で言う（例: 「打楽器の音をノート番号で書き出す」）。
2. `index.md` の「当たるべき場面」の欄で、それに当たる項目を探す。
3. 見つかったら、仕様の中身は推測せず、その項目の一次情報を開いて確かめる。開けなければ、開けなかったことを PR か Issue に書き、推測で書かない。
4. 見つからなければ、そう書いて進める。索引に足すべき標準だと思ったら、`index.md` に項目を足す PR を別に出す（今の作業に混ぜない）。

## 索引に書くもの・書かないもの

- 書く: 名前と発行元、何を決めているか（1 行）、一次情報の URL と入手の条件、状態（現行か、後継があるか）、当たるべき場面、middy との接点、確認日。
- 書かない: 仕様の本文や要約、版番号の細部、一次情報を開かずに書いた内容。
- 確認日は、一次情報を実際に開いて確かめた日。開けなかった項目には入れない。
- middy の記法と食い違う慣習は「middy との違い」として書く。直すかどうかは別の Issue にする。

## 置き場所の分担

- この索引は、開発の session で AI が引くためのもの。プロダクトの文書（`docs/`）には入れない。
- 人間が読む学習ログは GitHub Wiki に置いてよい（所有者の判断）。AI は開発の session では Wiki を読まない。
