# プロダクトビジョン

## 一文で

**作曲を学ぶ人が、頭の中の曲のイメージから鳴らせる具体的な例を受け取り、その例がどんな構成要素（調・テンポ・コード進行・リズム）と理屈でできているかを「聴いて・見て・理解できる」学習コンパニオン。**

リポジトリ説明（原文）:

> ユーザーの作曲スキルと音楽理論の理解・実践を助けるための、midi作成と再生とチャットを提供するwebアプリ。pwa対応。イメージをAIで解釈して、そのイメージに合うパターンを提示し、相談して、それにマッチした候補のタイムラインを回答。再生可能で、生成したそのトラックのコード進行やリズムの成り立ちも視覚的な支援を伴う形で解説してくれる。

## 解く問題

音楽理論の教材は「読んで理解する」ことを求めるが、学習者が本当に欲しいのは **自分の作りたい曲に理論がどう効くか** を体感することだ。既存の作曲 AI は完成品を吐き出すが、なぜそうなるかを教えてくれない。DAW は自由だが、何から手をつければいいか分からない。

middy は「イメージ → 理論に基づいた候補 → 再生 → 成り立ちの解説」という短いループを提供し、学習者が **自分の意図と理論の対応を繰り返し確かめられる** ようにする。

## ペルソナ

1. **はじめて作曲する人**（主ペルソナ）: 楽器は少し弾ける、理論は「コード進行」という言葉を知っている程度。頭の中のイメージを形にしたいが、何から始めればいいかわからない。
2. **独学で理論を勉強中の人**: ダイアトニックコード・ケーデンスは知っている。知識と実際の響きを結びつけたい。「このイメージなら ii-V-I が合う」と言われて納得したい。
3. **作曲経験者（副次）**: アイデア出しの壁打ち相手が欲しい。説明は飛ばして MIDI だけ欲しいことも多い。

設計はペルソナ 1〜2 のために行う。3 は積極的には狙わない。

## コアシナリオ（価値の高い順）

### S2. イメージから例をもらい、その成り立ちを知る（AI）

ユーザーの側にあるのは曲のイメージで、進行ではない。「雨の日曜の午後」と入力すると、AI がそれを解釈し（短調寄り・ゆったりしたテンポ・落ち着いた進行など）、鳴らせる具体的な例（候補）を 2〜3 個示す。ユーザーはまず例を聴き、次にその例がどんな構成要素とどんな理屈でできているかを解説で知る。「もう少し明るく」「サビっぽく」と相談して、候補を更新できる。

これが **ユーザーから見た middy** であり、他のシナリオはこれを広げる。

### S3. リズムをつけて曲らしくする

候補の進行に、伴奏パターンとドラムパターンが付く。リズムの成り立ち（拍の重心、シンコペーション、小節構造）も視覚的に解説される。

### S4. 持ち帰る

生成したタイムラインを Standard MIDI File として書き出し、DAW に読み込める。プロジェクトはブラウザに保存され、PWA としてインストールして使える。

## 土台となる能力

### S1. 進行を聴いて、成り立ちを見る（AI 不要）

調と進行（例: C major, I–V–vi–IV）からタイムラインを作り、その場で再生できる。再生中、今鳴っているコードがハイライトされ、ローマ数字と和声機能（T/S/D）、ケーデンスの説明が表示される。

S2〜S4 はすべてこの能力の上に載る。AI がなくても動くが、シナリオを成り立たせる中核の機能であり、ユーザーの入口ではない。

## 価値仮説と計測

| 仮説 | 検証方法（将来） |
| --- | --- |
| 解説つきで聴けると、理論の理解が「腹落ち」する | 解説パネルの展開率、同じ進行の繰り返し再生回数 |
| イメージからの候補提示は、白紙から始めるより着手が早い | 入力から初回再生までの時間 |
| チャットでの相談は候補の採用率を上げる | 相談後に候補が採用される割合 |

計測の仕組みはまだない（M4+ の候補、`roadmap.md`）。今は開発者自身がシナリオを通して確かめる。

## やらないこと（M4+ で見直す）

- ユーザー登録・ログイン・サーバー側の永続化（ローカル保存で十分）
- メロディ・歌詞の生成
- オーディオレンダリング（サーバー側）やサンプル音源の配布。再生はブラウザのシンセで行う
- ジャンル固有のリアルな打ち込み再現
- DAW プラグイン化、Web MIDI 出力
- 多言語対応（UI は日本語で始める）

これらは backlog の Later / Ideas に置き、コアシナリオが成立してから検討する。

## 成功の定義（M3 時点）

主ペルソナが、インストールした middy で「イメージ入力 → 候補の再生 → 解説を読む → MIDI を書き出す」までを **一度もドキュメントを読まずに** 完了できる。
