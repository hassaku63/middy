# 体験の設計（概念・流れ・画面の約束）

[intent.md](intent.md) の意思を、概念・流れ・画面の約束に落とした文書。書き方と各層の意味は [UI/UX 設計の原則と手順](../design/ux-principles.md)。実装の構成は [overview.md](../architecture/overview.md)。

## 概念

| 概念 | 目的 | 状態 | 操作 | 動作原理 |
| --- | --- | --- | --- | --- |
| **イメージ** | 曲のイメージを言葉で渡し、言い直して近づける | 会話の履歴 | 言う、言い直す、最初から | 「雨の日曜の午後」と言うと例が届き、「もう少し明るく」と言うと例が更新される |
| **例** | イメージを、鳴る具体的な形にする | 調・拍子・テンポ・進行・伴奏とドラムの型・ノリと、そのタイムライン。1 回の答えに 1〜3 個 | 聴く、別の例に切り替える、キーを変える、スタイルを替える | 例が届いたらすぐ聴ける。別の例に切り替えて聴き比べられる。キーを変えると、ローマ数字と拍子はそのままで音の高さだけが移る。スタイルを替えると、和声はそのままでそのスタイルのグルーヴになり、変わった部分だけが述べられる（どちらも AI には聞き直さない） |
| **成り立ち** | 例がなぜそう鳴るかを、鳴っている瞬間に示す | 再生位置、固定中のコード | コードを選んで止めて見る | 再生中、今鳴っているコードの機能と理由が、そのコードの隣に出る。止まっているあいだは、タイムラインのどの和音・音も「鳴っている」と強調しない（解説は最初の和音から読める）。その上に、例全体のモードとその性格（全体）と、進行の長さと区切り（流れ）が短く出て、再生しても動かない。モードの 7 つの和音を機能の色で並べた度数の地図が、例で使う和音を強調し、解説中の和音を光らせる（BL-099） |
| **とっておく** | 気に入った例を、あとで続きから聴ける | とっておいた例の一覧（ブラウザ内） | とっておく、外す、開く、名前を変える、消す | 例をとっておき、あとで開くと同じ例が鳴る |
| **書き出し** | 例を DAW に持ち出す | — | MIDI を書き出す | 例を書き出すと、DAW で同じ進行とリズムが鳴る |

- 進行（ローマ数字の並び）は、ユーザーが操作する概念ではなく、例を形づくる要素の 1 つ。進行から直接タイムラインを作る能力（vision の S1）は API とエンジンに残すが、画面の入口にはしない。例の進行を自分で変えることは、1 つの例に対するバリエーション（backlog の Ideas）として扱う。

## 流れ

中心の繰り返し: イメージを言う → 例を聴く → 成り立ちを見る → 言い直す。

| 段階 | ユーザーがすること | 画面に見えるもの |
| --- | --- | --- |
| 初めて開く（空） | 何を言えばいいかを知る | イメージの入力欄と、入力例 |
| 送って待つ | 待つ | 送った言葉と、考え中であること。入力欄は残る |
| 例が届く | 聴く例を選ぶ | 届いた例がカードで並ぶ。ユーザーが選ぶまで、どの例も選ばれていない（自動では開かない）。カードを押すと、その例が開く（BL-219）。カードの度数は絵と同じ書き方で、その下に実音のコード名を添える（#451）。カードには長さを小節数でも出す（BL-305） |
| 聴く | 聴きながら見る | 再生中のコードと、その成り立ちが隣に並ぶ |
| 比べる | 別の例に切り替えて聴く | 選んだ例のタイムラインと成り立ち |
| 言い直す | 言葉を足して送る | 入力欄。更新された例が届いても、直前に選んだ例が選ばれたまま開いている。届いた例は選び直す先として並ぶ。それまでのやり取りは畳まれる |
| 持ち帰る（繰り返しの外） | 保存する、書き出す | 例があるときだけ、従属した操作として出る |
| 失敗 | 言い直すか、待ってもう一度送る | 何が起きたかと、次にすることを、入力欄の近くに |

## 画面の約束

画面は 1 枚。広い画面では、会話を左の列（画面の 30 %、320〜400 px）に、結果をその右に置く。題名と説明の 1 行は会話の列の先頭に置き、結果はページの上端から始める（#436）。アプリのインストールは、題名の横の小さなボタン「アプリにする」で、ブラウザがインストールできるときだけ出す。帯の 1 行は使わない（#439）。会話の列でも、返事とカードが短い行で何度も折れないようにする（#437）。結果は、タイムラインを横いっぱいに描く（wide、#279）。1 和音の解説の枠には度数の地図を入れる。今の和音の解説と、地図の上のその和音は同時に読むものだから（#360）。地図の上の今の和音は、セルの外側の枠と動かない光で示し、色はタイムラインと解説の枠にそろえる（追従は琥珀、固定は青。ADR-0056）。結果の幅が足りれば、枠をタイムラインの上の帯にして、絵の最上段のコード列の隣に置き、全体の解説を下に 1 列で並べる。帯と全体の解説の箱は、地図と 40 字の文の幅で止め、右端をそろえる。広い画面で右が空いた箱にしない（#419）。狭ければ、どちらもタイムラインの下に並べる（窓の幅ではなく結果の幅で決める。#353、ADR-0044）。地図は、長調と短調では機能の流れ（T → S → D → T）の列に並べ、その下に「基本の流れ（いつもこの順とは限らない）」と添える。矢印だけでは規則に見えるが、V → IV のように戻る進行もあるから（#371）。機能は長調・短調の考え方なので、モードの例では、解説の機能の札、読み上げの機能名、地図の機能の色を出さず、地図の主和音に印を付ける。解説の文も機能を名指しせず、主和音か何度の和音かで始める（ADR-0045、ADR-0046）。モードでは代わりに和音の役割を見せる。地図は役割の列（主和音 → 特徴和音 → そのほか → 三全音）に分け、列は言葉の見出しと、列の中より広い列の間の余白で区別する（#402 の D）。解説の札と読み上げは役割の言葉にする（ADR-0047、ADR-0048）。解説の 1 行は 40 字までにする（WCAG 1.4.8 の CJK の上限）。タイムラインの高さには上限があり、再生中に解説の枠と同時に見える（ADR-0041）。上限に当たるときも幅は縮めず、小節を横に伸ばして横いっぱいに描く。文字と行の高さは変えない（ADR-0057）。結果の幅が絵より狭いとき（スマホ）は、絵を縮めずに横にスクロールし、行名の列を左に留める。絵には、コードの枠とは別に小節と拍の線を引く。小節の線は拍の線より濃くし、音符の下に描く（DAW の編集画面と同じ線の階層。#435）。コード列の上には小節番号を置き、再生位置の「3.1」の 3 と対応させる。縮小図の帯には出さない。描く文字は 12 px 以上、和音の押せる高さは 24 px 以上にする（ADR-0059）。狭い画面では会話と結果を縦に並べる。しきい値の値は `docs/dev/conventions.md` の「配置」の表にだけ書く。

- **主目的:** イメージから届いた例を聴いて、その成り立ちを知る。
- **主操作:** 例がないときは「送る」、例があるときは「再生」。再生中は同じ位置・同じ大きさのボタンが「停止」になる（今できる操作が目立つように。#402 の B）。
- **2 つの半分:** 会話（イメージ、返事、例のカード、入力欄）と、開いている例（再生、タイムライン、成り立ち）。例を開いているあいだ、その境目に線を引く。縦に並ぶときは横の線、横に並ぶときは縦の線（BL-212）。どちらの半分も、中のカードやパネルがすでに枠を持つので、半分ごとの枠では囲まない。
- **常に出す:** イメージの入力欄。
- **必要なときだけ出す:**
  - 例と、その切り替え: 例が届いてから
  - 例で表せなかったもの: AI がそう言ったときだけ。返事の要約のすぐ下に、小さく控えめな色で「AI の見立て」として出す（ADR-0061）
  - 再生、タイムライン、成り立ち: 例を選んでいるとき。成り立ちはタイムラインと同時に見える位置に置く。タイムラインは、4 小節までなら全体をそのまま描く（結果の幅が足りなければ横にスクロールする）。それより長ければ、横にスクロールする 1 本の絵にし、その下に全体の縮小図を細い帯で添える。帯は今見えている範囲を枠で示す（#360、編集ソフトの全体表示と同じ形）。再生中は、再生位置が端に近づくとページをめくるようにスクロールする。止まっているときは、固定したコードを中央に置き、固定がなければスクロールした位置に留まる。帯のコードを押すと、そのコードを固定してそこへ移る
  - キーの選択: 例を選んでいるとき。再生の隣に置く
  - 例の題名ととっておく星: 例を選んでいるとき。結果の上に題名を置き、その横に ☆（とっておいていない）／★（とっておいた）のボタンを置く。キーやスタイルを変えた例は別の例として扱う（BL-296）
  - 書き出し: 例を選んでいるとき。再生に従属させる
  - とっておいた例の一覧: 呼び出したとき
  - これまでのやり取り（最新の 1 往復より前）: 呼び出したとき
  - エラー、更新の通知、オフライン、接続の異常: 起きたとき
- **出さない:**
  - 入力方法の切り替え（入口はイメージだけ）
  - 正常なときの接続状態
  - 聴く前に読ませる解説。例の説明文は、聴く操作に従属させる
