# ロードマップ

マイルストーンは **ユーザーに見える価値の単位** で切る。各マイルストーンには「出口条件」があり、それを満たすまで次に進まない。順序は `vision.md` のコアシナリオの優先順位に従う。

| マイルストーン | テーマ | 対応シナリオ |
| --- | --- | --- |
| M0 | 足場 | — |
| M1 | Hear & See — 進行を聴いて成り立ちを見る | S1, S4 の一部（MIDI 書き出し） |
| M2 | Imagine — イメージから候補をもらい、相談する | S2 |
| M3 | Groove & Ship — リズム、保存、PWA 仕上げ | S3, S4 |
| M4+ | 広げる | 副次ペルソナ、計測、拡張 |

進捗（どのスライスが Done か）はこの文書には書かず、`backlog.md` を唯一の情報源とする。

## M0 — 足場

- モノレポ構成、Go バックエンド、React PWA の骨格
- 音楽ドメインの基礎型（Pitch, Key, Chord, Timeline）とテスト
- LLM 境界（interface + fake）
- `make check` と CI、AI 向けドキュメント、ADR、backlog

## M1 — Hear & See

**出口条件**: 調と進行（ローマ数字）を選ぶと、ブラウザでピアノ伴奏として再生でき、再生中のコードがハイライトされ、ローマ数字・和声機能・ケーデンスの説明が表示され、SMF をダウンロードできる。LLM は一切使わない。

**なぜ先か**: AI がなくても学習価値があり、M2 の候補提示も結局はこの再生・解説の上に乗る。決定論的でテストしやすく、ドメインモデルの妥当性を早く検証できる。

## M2 — Imagine

**出口条件**: 自由文のイメージを入力すると、2〜3 個の候補（調・テンポ・進行・短い理由）が返り、それぞれ M1 の仕組みで再生・解説できる。チャットで制約を足すと候補が更新される。LLM の応答はすべて構造化出力で受け取り、エンジンで検証してから返す。fake LLM で CI が完結する。

## M3 — Groove & Ship

**出口条件**: 候補に伴奏・ドラムパターンが付き、リズムの成り立ちが視覚的に説明される。プロジェクトがブラウザに保存され、再訪時に復元される。PWA としてインストールでき、オフラインでも保存済みプロジェクトを再生できる。

## M4+ — 広げる

候補: ユーザー計測、モード拡張（ドリアン等）、借用和音・セカンダリドミナント、メロディ生成、Web MIDI 出力、共有リンク。すべて `backlog.md` の Later / Ideas から、M3 の学びをもとに選ぶ。各マイルストーンを構成したスライスは git log と PR に残り、この文書には書かない。
