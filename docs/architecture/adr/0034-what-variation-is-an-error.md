# 0034. 提案のゆらぎは許し、答えの中の理論の誤りと食い違いは許さない

- 日付: 2026-11-09
- 状態: Accepted（所有者の判断は #272。ADR-0003 の境界を、AI が書く文の検査にまで延ばす）

## 文脈

ADR-0003 で、音符・和音・分析はエンジンが作り、AI は解釈と対話を担う。エンジンの解説は決定論的で、テストで担保している。一方で、AI が書く文（返事の `summary`、候補の `reason`）に含まれる音楽理論の主張は、何も照合していない。

所有者が「丸の内サディスティック風の進行」と入力した例（#272）では、次の誤りが出た。

- 王道進行（IV–V–iii–vi）を「丸サ進行の骨格」と呼んだ。
- `subV7/vi`（B♭7）を F7 と書き、実際には次にない vi7 へ「滑り込む」と書いた。
- 候補どうしの派生関係を逆に書いた。

さらにエンジン自身も、IV の直前の `I7` を「IV へ向かう働きではない」と解説した。

学習のアプリにとって、理論として誤った説明は価値を損なう。一方で、同じ入力から違う例が出ることや、元の入力をアレンジすることは、価値の一部である。どこからを問題とみなすかを先に決める。

## 決定

1. **許すゆらぎ**: 音楽的に成り立ち、リクエストから逸脱しすぎていない提案。
   - 同じ入力から違う調・テンポ・拍子・スタイル・進行が出ること。
   - 名の知れた進行をアレンジすること（丸サ進行から v7 を省く、ループの終わりを変えるなど）。
2. **慣例的ではないが成り立つもの**も許す。ただし、解説は実際の動きのとおりに書く。
   - 例: V7 から IV へ戻る、ブルースの属七をトニックとして鳴らす。
   - 解決しないものを「解決する」と書かない。
3. **許さない誤り**: 次の 5 つ。
   1. 和音名・度数と、実際に鳴る和音の不一致（`subV7/vi` を F7 と書く）
   2. 解決先や前後の和音についての主張が、データと合わない（「vi7 へ進む」と書いて、次が IVmaj7）
   3. 名の知れた進行の呼び名の誤用（その呼び名を決めている特徴を欠く進行を、その名で呼ぶ）
   4. 候補どうしの派生関係の誤り（「A を B に替えた版」と書いたのに、差分がそうなっていない）
   5. 1 つの答えの中での食い違い（エンジンの解説と実際の進行、AI の文とエンジンの解説）
4. **誤りは仕組みで止める。** 次の 3 つで止める。
   - エンジンの解説は、ラベルだけでなく前後の和音を見て書く。
   - AI の文は、決定論的に照合できる主張（和音名、ローマ数字、解決先）を候補のデータと突き合わせ、合わなければ出し直させる。
   - 照合しきれないもの（呼び名、派生関係、言い回し）は、文脈を共有しない別の AI のレビューで、評価のときに数える。
5. **AI の理由の文は残す。** 理論の主張を含んでよい。ただし上の照合に通ったものだけを出す。

## 検討した選択肢

- A: 誤りの区分を決め、照合とレビューで止める。AI の理由の文は残す（採用）。
- B: AI の理由の文から理論の主張をなくし、印象だけにする。利点: 誤りの入り口が減る。欠点: 「なぜこの例がイメージに合うか」を理論の言葉で結ぶ説明が消える。所有者は理由を残したい。
- C: 正解の進行をケースごとに固定し、外れたら落とす。欠点: 解釈のゆらぎまで誤りにしてしまう。所有者の方針（アレンジは許す）に反する。

## 結果

- 「答えとして正しいか」の判定基準ができる。評価とレビューは、決定 3 の 5 つの区分で数える。
- エンジンの解説には、前後の和音を見る規則が増える。
- AI の文の照合で出し直しが増えると、待ち時間と費用が増える。評価で出し直しの率を見る。
- 呼び名や派生関係の取りこぼしが続くなら、AI に構造化した欄（呼び名、元の候補）で宣言させ、エンジンが検証する形を検討する（#272 の選択肢 3）。
