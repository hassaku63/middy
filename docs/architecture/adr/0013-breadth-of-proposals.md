# 0013. 提案の幅は「表せる空間」と「選ぶ振る舞い」に分けて、測ってから広げる

- 日付: 2026-11-08
- 状態: Accepted

## 文脈

### 観察

実 API で試すと、イメージが違っても `i - VI - III - VII - iv - i - iv - V` のような短調の循環と、アルペジオの伴奏がよく出る。「ケルト」のように、長調・短調とは別の体系（旋法）を土台にする音楽を頼んでも、印象に沿わず、今あるものの中からの提案になる。所有者は、提案の幅をもっと広げたい。

### 問い

幅の狭さは、(a) 仕様がそもそも表せないせいか、(b) 表せるのに AI が選ばないせいか、(c) 幅を測る手段がないせいか、(d) プロダクトの範囲（旋律や音色を作らない）のせいか。

### 幅が失われる場所

提案は、ユーザーの言葉 → AI の解釈 → インテント（スキーマとプロンプトの制約） → 検証と正規化 → エンジンの描画 → 解説 → カード、の順に流れる。幅はどの段階でも失われうる。調べた結果は次のとおり。確かな事実と推測を分けて書く。

| 段階 | 何が起きているか | 確度 |
| --- | --- | --- |
| **1. 表せる空間（契約）** | 調は 12 の主音 × 長調・短調だけ（`music.Mode` は `Major` と `Minor`）。和音はその調のダイアトニックな三和音と七の和音だけ。唯一の例外が、短調の和声的 V / V7。旋法（ドリアン、ミクソリディアン）、借用和音（長調の ♭VII、iv）、セカンダリードミナント、ブルースの I7 は表せない。短調で選べる「別の色」は、自然短音階の和音と和声的 V だけであり、`i - VI - III - VII` と `iv - V` はそれを使い切った形にほかならない | 事実（コード） |
| **2. 黙って直される** | エンジンは和音の質を調から決めるので、ローマ数字の大文字・小文字は短調の V 以外では無視される。D minor の `IV` は `iv`（Gm）に、D major の `VII` は `vii°`（C#dim）に、D minor の `VIImaj7` は `VII7`（C7）になる。`bVII` は検証で落ちる。AI が旋法らしく書いても音は長調・短調に戻り、しかもカードには AI の書いたラベルがそのまま出るので、表示と音が食い違う | 事実（手元で確認） |
| **3. プロンプトの誘導** | 「最初の候補をもっとも素直なものにする」「借用和音は使わない」とある。候補どうしの違いは求めているが、イメージに固有の要素を使うことは求めていない。語彙の例（ii7、V7、IVmaj7、viiø7）がそのまま出やすい | 事実（文面）。効果の大きさは未測定 |
| **4. AI の振る舞い** | 言語モデルは、学習データで頻度の高い進行（`I - V - vi - IV`、`i - VI - III - VII`）に寄る。`effort` は `low` に固定で、環境変数では変えられない。Opus 5.5 では temperature を指定できないので、ばらつきはプロンプトと考える量に頼るしかない | 推測（一般的な性質）。未測定 |
| **5. 測っていない** | 評価セットは、最初の候補の長調・短調、テンポ帯、ノリしか見ない。進行の種類の数や、同じ循環の繰り返しは数えていない。ケルト、ブルース、フラメンコのような、背景の違うケースは 1 件もない。したがって、観察は今のところ逸話であり、仮説を確かめる道具がない | 事実（コード） |
| **6. 描画と解説** | 伴奏 5 種、ドラム 3 種、ノリ 2 種の有限のカタログ（ADR-0012 で扱う）。ボイシングは基本形の密集配置だけ、音色はピアノとギターだけ、拍子は 4/4 だけ。解説の機能（T/S/D）は度数で固定していて、旋法の和音を説明する語彙がない | 事実（コード） |
| **7. プロダクトの範囲** | 旋律を作らない（vision の「やらないこと」）。ケルトらしさの多くは、旋律の音階、持続音（ドローン）、3 度を抜いた 5 度の和音、6/8 のジグ、フィドルや笛の音色にある。和声だけでは「ケルト風の骨組み」までしか作れない | 事実（vision）と、音楽の知識 |

### 診断

- **1 と 2 と 4 は互いに強め合う。** 「長調・短調の教科書的な和音」しか表せないとき、「ケルト」「ジャズ」「少し変わった短調」のどれを頼まれても、AI にとって最も近い表現は同じ短調の循環になる。幅の狭さの大半は、ここで決まっていると考える。
- **旋法（モード）を足すだけでは解消しない。** 1 は直るが、4 と 5 は残る。足したあとは「いつも同じドリアンの循環」として現れるはずである。2 を直さなければ、足した旋法の和音も黙って直される。
- **7 は別の種類の問題。** 旋律・音色・拍子は、プロダクトの範囲の判断である。ただし、理論を学ぶ道具として見れば、「ドリアンでは IV が長三和音になる」ことを聴いて見せること自体が学習の価値であり、旋法は範囲の内側にある。音色（GM のプログラム番号）と 6/8 は、ADR-0012 の「スタイル」と「グルーヴ」で扱える。旋律は引き続き範囲の外に置く。
- **3 と 4 は、1 を直さなくても調べられる。** そのための道具が 5 である。

### 用語

- **スケール（音階）**: 音を高さの順に並べた集合。長音階、自然短音階、和声的短音階、ペンタトニックなど。
- **モード（旋法）**: ある音階を、どの音を中心に聞かせるかで区別したもの。長調はイオニアン、自然短音階はエオリアンで、どちらもモードの 1 つ。同じ白鍵でも、D を中心にすればドリアンになる。
- **調（キー）**: 主音とモードの組み合わせ。今の middy は、モードを長調と短調の 2 つに絞った調しか持たない。
- 画面と文書では「モード」を使い、初出で「（旋法）」を添える。コードの `Key.Mode` と一致させる。

## 決定（提案）

1. **先に測る。** 評価セットに、提案の幅の指標（進行の種類の数、最も多い進行とその回数、使った語彙の割合、調の種類の数）と、背景の違うケース（ケルト、ブルース、フラメンコ、ロック、J-pop の王道進行、ボサノバ）を足す。評価のときだけ、AI に「エンジンの制約がなければ本当は何を書きたかったか」を自由記述で添えさせ、「表せない」と「選ばない」を切り分ける。この欄はエンジンでは使わず、本番の要求にも入れない。
2. **黙って直さない。** ラベルの大文字・小文字や七の和音の種類が、調から決まる和音と食い違ったら、検証で落として「D minor では `IV` は Gm（`iv`）になる」と伝えて再試行させる。カードはエンジンの表記で出す。これは幅の問題であると同時に、表示と音の食い違いという正確さの問題でもある。
3. **測った結果で、プロンプトと考える量を調整する。** 「最初は素直に」は残し、「他の候補はイメージに固有の要素を使い、定番の循環から離れる」を足す。`effort` を環境変数で変えられるようにし、`low` と `medium` を評価セットで比べる。費用と速さの差も記録する。
4. **足りない理論の概念を埋める。** 目標は「ケルト風が出せる最低限」ではなく、音楽理論の概念として対応していない範囲（モード、やがて借用和音やセカンダリードミナント）を埋めること。ケルトのような依頼は、その欠けを見つけるための例として使う。モードはまずドリアンとミクソリディアン（ケルト、ロック、モーダルなジャズの土台）。次にフリジアン（フラメンコ）とリディアン。これは、調の体系、エンジンの音階と和音、ローマ数字の読み取り、解説（T/S/D ではなく特徴音で語る）、綴り、スキーマ、プロンプト、評価セット、画面のモード名に及ぶ変更なので、着手前に専用の ADR を書く。方針は次のとおり。
   - モードは調の属性（`Key.Mode`）として足す。借用和音（BL-075）は、長調・短調の曲の中の局所的な色として別に扱う。曲全体がドリアンならモード、長調の曲に一瞬 iv が出るなら借用。
   - 解説は、モードの特徴音（ドリアンの長 6 度、ミクソリディアンの短 7 度）を含む和音を指して語る。終止も、旋法の終止（ミクソリディアンの ♭VII–I、ドリアンの IV–i）を足す。
   - 音名の綴り（BL-079）は、モードの親となる長調の調号から決める。D ドリアンは C major の調号で綴る。BL-079 はこれを見越して設計する。
   - キーの変更（BL-078）は、ローマ数字がそのまま使えるのでモードをまたいでも動く。
5. **旋律は作らない。** ジャンルの再現もしない（vision）。音色と 6/8 は、ADR-0012 のスタイルとグルーヴの範囲で後から検討する。
6. **1〜4 の順番は既定。** 所有者の判断で、まとめて一度に実装する進め方に切り替えてもよい。その場合も、測る道具（1）は最初の PR に含める。

## 検討した選択肢

- **モードを足せば解決するとみなす:** 1 だけを直し、4 と 5 を放置することになる。足したあとに同じ問題が形を変えて残る。
- **プロンプトだけで幅を広げる:** 表せない空間はプロンプトでは広がらない。2 の「黙って直す」が残れば、AI が工夫した分だけ表示と音がずれる。
- **AI に音符や音階を直接書かせる:** ADR-0003 に反し、説明できなくなる。
- **ランダム性（temperature）に頼る:** 対象モデルでは指定できず、できたとしても幅ではなく揺らぎが増えるだけで、学習の価値（意思 1）にはつながらない。
- **「素直な候補を最初に」をやめる:** 初めて作曲する人（主ペルソナ）には、最初の候補が王道であることに価値がある。残して、2 つ目以降で幅を出す。

## 結果

- 幅の問題を「表せる空間」と「選ぶ振る舞い」に分けて扱えるようになり、どちらを直したかを評価セットで示せる。
- 旋法を入れる前に、表示と音の食い違い（2）が直る。
- 評価セットが、長調・短調の判定から、幅と語彙の判定へ広がる。費用は 1 回あたり数十円増える。
- 再検討の条件:
  - 測定の結果、「書きたいもの」も定番に寄っていた（選ばない側が主因だった）場合は、モードより先にプロンプトと `effort` の調整に比重を移す。
  - モードを足したあとも同じ循環の繰り返しが減らない場合は、候補ごとに「使う特徴音」をインテントで明示させることを検討する。

## 所有者の判断

- 進め方の順番（測る → 黙って直さない → 調整する → 概念を埋める）を既定とする。
- 目標は、理論の概念として対応していない範囲を埋めること。ケルト風の再現そのものではない。
- 最初のモードはドリアンとミクソリディアン。
- 評価のときだけ、AI に自由記述の欄を添えさせてよい。
