# 0059. 狭い画面のタイムラインは縮めずに横へスクロールし、行名の列を左に留める

- 日付: 2026-11-11
- 状態: Accepted

## 文脈

4 小節までのタイムラインは、結果の幅に収まるよう縦横比を保って縮めていた（CSS の `width: 100%`）。390 px の幅では絵が約 0.5 倍になり、行名と和音の文字は 6〜7 px、和音の押せる高さは 20 px ほどになった（#402 の A）。所有者は、縮めずに小節の幅を保って横スクロールにすることを選んだ。

## 決定

- タイムラインは、どの長さでも横スクロールの箱 1 つに入れる。箱の木の形は幅で変えない（ADR-0042）。
- 箱の中の絵は、自分の大きさ（BAR_WIDTH の 160 px）より小さくしない。結果の幅のほうが広ければ、今までどおり幅いっぱいに描き、高さの上限（画面の 45 %）に当たるときは小節を横に伸ばす（ADR-0057）。
  - 高さの上限は今までどおり守る。上限が絵の高さより低い画面（横向きのスマホなど）では、その分だけ縮む。
- 行名（音名と打楽器の名前）の列は、箱の左に `position: sticky` で留める重ねの絵（`TimelineLabels`）として描く。絵の中の行名の列と同じ大きさで重ね、場所を取らない。支援技術には隠す（絵の中の同じ文字と重複するため）。
- 行名の文字は 12 px（`LABEL_FONT`）にし、打楽器の行の高さは 16 px にする。
- 箱は、短いタイムラインでも、再生位置か固定した和音を見える範囲に保つ（長いときと同じ規則）。

## 検討した選択肢

- A: 縮めたまま文字だけ大きくする。欠点: 小節の中の音符が細くなりすぎ、行名が行の高さに収まらない。
- B: 縦に回す（時間を下向きにする）。欠点: 広い画面と読み方が変わり、和音の帯と並べる配置（#360）が崩れる。
- C（採用）: 縮めずに横スクロールにし、行名の列を留める。利点: 文字と押せる大きさを保ち、広い画面と同じ読み方のまま。欠点: 短い例でも全体が一度に見えない。

## 結果

390×844 で、描かれた文字は 12 px 以上、和音の押せる高さは 24 px 以上になり、スクロールしても行名の列は左に留まる。ページそのものは横にスクロールしない。E2E の `layout.spec.ts` が確かめる。

短いタイムラインには全体の縮小図を付けない。4 小節なら、スクロールの幅は画面 2 枚分ほどで足りるから。
