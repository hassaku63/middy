# 0078. コードの列は Tab の止まり先を 1 つにする

- 日付: 2026-11-14
- 状態: Accepted（所有者の判断。#500）

## 文脈

タイムラインのコードの列（`ChordLane`、`role="listbox"` / `option`）は、和音 1 つ 1 つが Tab の止まり先だった。16 個の和音がある曲なら、列を通り抜けるのに Tab を 16 回押す。解説や書き出しに行くまでが長い。

WAI-ARIA の実装例集（APG）のリストボックスは、列全体を 1 つの止まり先にする。中は矢印キーで動く（`.claude/skills/hci/index.md` の「支援技術」）。一方、この画面には、どこにフォーカスがあっても ← → で前後の和音を固定するキー操作がすでにある（`app/useChordKeys`、BL-185）。

## 決定

1. **列の止まり先は 1 つ**（roving tabindex）。固定した和音、なければ鳴っている和音、なければ最初の和音が `tabIndex=0` で、ほかは `-1`。
2. **列の中のキー**
   - ← →: 今までどおり前後の和音を固定する（`useChordKeys`）。
   - Home / End: 最初と最後の和音を固定する。
   - Enter / Space: その和音を固定する。
   - Esc: 追随に戻す。
3. **フォーカスは固定についていく**（`useFocusFollows`）。フォーカスが列の中にあるとき、固定した和音へ移る。選択はフォーカスに従う（APG の「selection follows focus」）。

## 検討した選択肢

- 1 つの止まり先と roving tabindex（採用）。今の ← → の意味を変えずに、Tab の回数だけを減らせる。
- `aria-activedescendant` で、フォーカスは列に置いたまま、今の和音を属性で示す。SVG の `g` で支援技術との相性を確かめる手間が大きい。
- 今のまま、和音ごとに止まる（所有者が採らなかった）。

## 結果

- 列を通り抜けるのは Tab 1 回になる。
- 列の中で ← → を押すと、和音が固定され、フォーカスも移る。止まっているときは、固定した和音の名前と機能が読み上げられる（ADR-0076）。
- 縮小図の帯（`stretch`）の列は、今までどおり止まり先を持たない。
