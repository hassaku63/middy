# 0005. 縦スライスとバックログ規律による開発

- 日付: 2026-11-07
- 状態: Accepted

## 文脈

AI エージェントは「あったほうがいい」機能やリファクタに飛びつきやすく、レイヤーごと（まず全モデル、次に全 API…）に作ると価値が出るまでが長い。人間のレビュー負荷も PR サイズに比例する。

## 決定

- 作業単位は **縦スライス**（ドメイン → API → UI を貫く、ユーザーが触れる最小の価値）。`docs/product/backlog.md` に ID 付きで並べる。
- **Now / Next / Later / Ideas** の 4 段階。エージェントは Now の上から `Ready` を 1 つ選ぶ。Now にない機能は実装せず、Ideas に 1 行書く。
- 1 スライス = 1 PR。目安 400 行差分以内。超えるなら分割して backlog を更新する。
- 受け入れ条件をスライスごとに書き、満たしたら `Done` に移す。
- 「完了の定義」は `docs/dev/workflow.md`。`make check` 緑、テストあり、ドキュメント更新、スコープ外の明記。

## 結果

- 各 PR の後に必ず動くものが増え、ドメインモデルの誤りが早く見つかる。
- 横断的な整理（共通化など）は後回しになりがち。それ自体を backlog のスライスとして扱い、必要になった根拠（重複が 3 箇所以上など）を添える。
