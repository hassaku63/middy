# 0044. 1 和音の解説を地図と同じ枠に入れ、広い画面ではタイムラインの上の帯にする

- 日付: 2026-11-10
- 状態: Accepted

## 文脈

広い画面では、タイムラインの下に 1 和音の解説の枠と全体の解説（全体・流れ・度数の地図・リズム）を左右 2 列に並べていた。高さの違う 2 列の下に、大きな空白が残っていた。所有者はこれを最大の違和感として挙げた（#360）。

近接の原則で整理した（#360 のコメント）。結びつけて読む必要が最も強い対は、「鳴っている和音（コード列）」と「1 和音の解説」の組で、その次が「1 和音の解説」と「度数の地図」の組。コード列はタイムラインの絵の最上段にある。度数の地図は今の和音を光らせるので、再生と一緒に動く情報なのに、止まっている全体の解説の群に入っていた。

所有者は、案 R1′（動くものをタイムラインの上の帯に集め、止まっているものを下に 1 列に）をベースにすることを選んだ。あわせて、次の 2 点を求めた。

- 地図を、7 個の横並びよりよい形にする。
- 解説と地図の距離を縮める。左右は時間の流れとして読まれるので、解説の右に余白を挟んで地図が来るのは遠い。

音楽理論の図示を比べると（#360 のコメントと、所有者が公開した記事）、機能の流れ（T → S → D → T。Open Music Theory の phrase model）は向きがタイムラインと同じ左→右で、表示を変えるだけで作れる。ただし、機能（T・S・D）は長調と短調の考え方で、モードでは成り立ちにくい（ADR-0015 は、モードでも度数で機能を付ける単純化を選んでいる）。

## 決定

- 度数の地図を、1 和音の解説の枠（`ChordFrame`）の中に置く。枠が共通領域になり、光った和音と解説の見出しの間に余白がない。
- 結果の幅が広いとき（`@container stage` の 760 px 以上）は、枠をタイムラインの上の帯にし、地図をその左、1 和音の解説を右に置く。全体・流れとリズムは、タイムラインの下に 1 列で並べる。狭いときは、今までどおり、どちらもタイムラインの下に置く。部品の木は幅で分けず、CSS の `order` と `display: contents` で並びを変える（ADR-0042 の、状態を保つ規則）。
- 地図は、長調と短調では機能の列（T → S → D → T。1 列は 2 段まで）に並べ、モードでは度数の順のまま並べる。機能の割り当てはエンジンの `Overview.degrees` をそのまま使い、新しい理論は足さない。
- 1 和音の解説の文の部分は大きさが一定で、長い文は中でスクロールする。帯では 5 行、狭いときは 6 行。

## 検討した選択肢

- R1（帯を上、全体は下に 1 列。地図は全体の中）: 解説と地図が離れる。
- R2（R1 の全体を左右 2 段）: 2 段の高さの差で空白が残る。
- R3（帯をタイムラインのすぐ下）: コード列から遠い。
- 地図を解説の右に置く: 左右は時間の流れとして読まれ、余白を挟むと遠い（所有者の指摘）。
- 地図を解説の上に縦に置く: 縦の場所を使う（所有者の評価は微妙）。
- 全モードで機能の列にする: ADR-0015 の単純化を、地図の形で強く打ち出してしまう（フリジアンの ♭II、ミクソリディアンの v）。
- Chord Flow Chart（T の延長の列、和音どうしの矢印）、三度圏、五度圏: 理論の判断が要るか、場所を取る。backlog の Ideas に送る。

## 結果

- 1920×1080 で、帯（地図と 1 和音の解説）、タイムライン、縮小図、全体の解説の頭が 1 画面に入る。
- モードの例では、地図の形が長調・短調と違う。機能の説明をモードごとに見直すときは、ADR-0015 と一緒に扱う。
- 狭い画面では、枠に地図が入った分だけ高くなる（スマホで約 380 px）。
