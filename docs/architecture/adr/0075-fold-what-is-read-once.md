# 0075. 例ごとに 1 回読む解説は、個別にたたむ

- 日付: 2026-11-13
- 状態: Accepted（所有者の判断。#511 の 3 と 4。BL-298 の「解説の先頭に置く」を置き換える）

## 文脈

解説のパネルには、次の 3 つが並んでいた。
- 「この例（AI の提案）」: イメージ、キー・テンポ・長さ、進行、和音名、スタイル、理由。BL-298 で、解説の先頭に置いた。
- 「全体と流れ」
- 「リズム」

所有者は、解説の部品に表示の優先順位を付けた（#511）。
- 再生中に読むもの（今のコードの解説と度数の地図）は、いつも見せる（ADR-0074）。
- 例全体についてのものは、はみ出してよく、スクロールやたたむので足りる。

「この例」は、会話の列にある例のカードとほぼ同じ中身。「リズム」も、例を替えるかスタイルを変えるまで変わらない。どちらも例ごとに 1 回読めばよい（#511 の層 3）。

## 決定

1. **「この例」と「リズム」は、個別にたたむ。** 最初はたたんでおき、それぞれの見出しの横に要点を添える。
   - この例: キー・テンポ・小節数
   - リズム: 伴奏・ドラム・ノリの名前
   - 1 つにまとめない。見出しで中身が分かり、必要なものだけ開けるようにするため。
2. **「全体と流れ」は開いたまま、パネルの先頭に置く。** たたんだ 2 つは、その下に置く。
3. **HTML の `details` と `summary` で作る**（`shared/ui/Fold`）。キーボードで開け閉めでき、画面読み上げが開いているかを伝える。開け閉めの状態は、別の例を開いても保つ（要素が残るため）。
4. **コピーは、たたんでいても全部を写す**（BL-300 のまま）。

## 検討した選択肢

- 個別にたたむ（採用）。
- 「例の詳細」として 1 つにまとめてたたむ。中にリズムがあることに気づきにくく、開くと両方が出る。
- たたまずに、全体と流れを先にするだけ。パネルの長さは変わらない。

## 結果

- 解説のパネルは、たたんだ状態で短くなる。全体と流れが、結果の中で上に来る。
- たたんだ中身は、ブラウザのページ内検索の対象から外れることがある（ブラウザによる）。
- 再検討の条件: 「この例」の理由の文を読まれなくなった、という声が出たとき。
