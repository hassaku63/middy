# 0022. 存在しないファイルは 404 にし、SPA に振り分けるのは画面の URL だけにする

- 日付: 2026-11-09
- 状態: Superseded by ADR-0027（規則は nginx の設定に移る。移行が終わるまでは Go の実装が持つ。BL-148）

## 文脈

ADR-0008 の決定 1 は、`/api` 以外で見つからないパスに、すべて `index.html` を 200 で返すと決めた。画面の URL（`/projects/42` など）を直接開いても、アプリが立ち上がるようにするためである。

この規則は、ファイルを指す URL にも当てはまっていた。デプロイでビルドのファイル名（`/assets/index-<hash>.js`）が変わったあと、古い画面を開いたままのタブや Service Worker が古いファイルを求めると、サーバーは HTML を 200 で返す。すると、次の問題が起きる。

- ブラウザは JS のつもりで HTML を受け取り、MIME の不一致で読み込みに失敗する。「無い」とわからないので、読み込み直しや取り直しの手がかりがない。
- Service Worker や途中のキャッシュが、その HTML を JS の URL のものとして保存しうる。
- 存在しない内容に 200 を返すのは、一般的な Web アプリの振る舞い（SPA の振り分けは画面のナビゲーションだけ）と違う。

## 決定

1. 見つからないパスのうち、ファイルを指すもの（`assets/` の下、または拡張子を持つもの）は、404（JSON の `not_found`、`Cache-Control: no-cache`）を返す。
2. それ以外の見つからないパス（画面の URL）は、今までどおり `index.html` を返す。
3. `/api` の下の扱い（JSON の 404 と 405）は変えない。

## 検討した選択肢

- A: 今のまま（すべて `index.html`）。利点: 変更がない。欠点: 上の問題が残る。
- B: ファイルを指すパスだけ 404（採用）。利点: 変更が小さく、配信形態（単一バイナリ、ADR-0008）を変えない。一般的な SPA の配信と同じ振る舞いになる。欠点: 画面の URL に拡張子を使えなくなる（今は使っていない）。
- C: フロントの配信を nginx などに任せ、ルーティングをそちらで行う。利点: 一般的な構成で、キャッシュや 404 の設定を標準のやり方で書ける。欠点: ADR-0008 の配備形態（単一バイナリ）を変える重い判断になる。backlog の Ideas に、別の企画として置いた。

## 結果

- デプロイのあとに古いタブが古いファイルを求めても、404 になる。HTML を JS として扱う失敗がなくなる。
- 画面の URL に拡張子（`.` を含む最後の要素）を使うと、404 になる。画面の URL を足すときは拡張子を付けない。
- 配信を nginx などに移すと決めたら（C）、この規則はそちらの設定に移し、この ADR を置き換える。
