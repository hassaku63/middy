# 0073. 高さの低い横画面では、会話を引き出しにする

- 日付: 2026-11-13
- 状態: Accepted（所有者の判断。#498 の推奨 B）

## 文脈

配置を切り替える条件は、画面の幅 1024 px の 1 か所だけだった（ADR-0042、`docs/dev/conventions.md` の表）。

スマホを横にすると（844×390 など）、幅は 1024 px 未満なので、会話と結果が縦に並ぶ。その結果、次のことが起きていた（#498 の計測）。
- 例を開いても、画面に出るのは会話の列だけ。タイムラインは約 1000 px 下にある。
- タイムライン（約 180 px）と解説の枠（約 230 px）は、縦に積むと画面の高さに収まらない。そのため、再生中に 2 つを同時に見られない（ADR-0041 の目的に反する）。

スマホを横にする人は、タイムラインを広く見ながら聴きたいのだと考えた。会話の入力は、縦向きのほうがしやすい（キーボードが画面の半分を占めるため）。

## 決定

1. **条件は「横向きで、高さが 500 px 以下」**（`(orientation: landscape) and (max-height: 500px)`）。
   - 500 px は、内容から決めた値。タイムライン（画面の高さの 45 % が上限）と解説の枠（約 230 px）を、ツールバーと一緒に縦に積むと、収まらなくなる高さ。
   - 端末の種類では決めない。CSS の media query だけで切り替える。
2. **例を開いたら、会話の列をたたむ。**
   - たたんだ会話は、結果の左端に重なる引き出し（幅 380 px まで）になる。ツールバーの「会話」で開き、引き出しの頭の「会話を閉じる」で閉じる。
   - 手で開け閉めしたときは、フォーカスが開いた側のボタンへ移る。
   - 例を開いていないあいだは、会話がそのまま画面を使う。
3. **結果は画面いっぱいに広げ、タイムラインを左、解説の枠と全体の解説を右に並べる。**
   - ページは 1 画面の高さ。右の列だけが、その中でスクロールする。
   - 右の列の中は、狭いときの並びにする。1 和音の解説が先、度数の地図がその下。再生中に読む文が、スクロールせずに見える。
   - タイムラインの高さの上限は、画面の高さからツールバーと帯の分を引いた値にする（`--timeline-max-height`）。
4. **部品の木は変えない。** 開け閉めの状態は `App` が持ち（`useChatDrawer`）、それ以外の画面では使われない。スマホを回しても、入力中の文字と固定した和音は残る（ADR-0042）。

## 検討した選択肢

- A: 高さの低い横画面でも 2 列にするだけ。結果の幅が約 520 px で、タイムラインと解説の枠は縦に並ぶので、同時には見えない。
- B: 会話を引き出しにして、結果を全幅に広げる（採用）。
- C: 例を開いたら結果までスクロールする。スマホ横では、2 つを同時に見られないまま。タブレットの縦向き（820×1180 など。タイムラインが最初の画面の外）には効く。#498 で別に扱う。
- D: 何もしない。

## 結果

- スマホを横にすると、タイムラインと解説の枠を同時に見ながら聴ける。
- 横向きのスマホでは、高さに合わせてタイムラインの絵が縮み、文字が小さくなる。
- 再検討の条件:
  - 引き出しに気づかない、または会話に戻りにくい、という報告が出たとき。
  - 折りたたみ端末や分割画面で、条件が合わない高さが見つかったとき。
