# 0057. タイムラインは結果の幅いっぱいに描き、高さの上限は小節を横に伸ばして守る

- 日付: 2026-11-11
- 状態: Accepted（ADR-0041 の「縦横比は保つ」を置き換える）

## 文脈

画面の約束は、タイムラインを「横いっぱい」に描くことと、「高さは画面の 45 % まで」（ADR-0041）の両方を求めていた。ADR-0041 は縦横比を保つので、上限に当たるとタイムラインは結果の幅より狭くなり、右に余白が残った。音域の広い例では、1280×800 でも右に 130〜170 px 空いた（#402 の F）。所有者は、幅を優先し、行の高さを保ったまま小節を横に伸ばすことを選んだ。

## 決定

- 結果の中のタイムラインは、結果の幅いっぱいに描く。高さは今までどおり、画面の 45 % を上限にする。
- 上限に当たるときは、絵を縮めずに、小節の幅（BAR_WIDTH の 160 px から）を広げる。広げ幅は、箱の縦横比に合わせて決める（`fitBarWidth`）。
  - 時間の向きだけが伸びる。行の高さ、文字、記号の大きさは変わらない（SVG の `preserveAspectRatio="none"` のように文字を潰さない）。
- 箱の大きさは、タイムラインの要素そのものを `ResizeObserver` で測る。窓の大きさは読まない（ADR-0042）。
- 長いタイムライン（横スクロールの箱、ADR-0041 の後の #360）と縮小図には当てない。

## 検討した選択肢

- A: 今のまま縦横比を保ち、右の余白を約束に書く。欠点: 約束の「横いっぱい」と食い違う。
- B: `preserveAspectRatio="none"` で引き伸ばす。欠点: 文字と記号が横に潰れる。
- C（採用）: 小節の幅を広げる。利点: 文字は潰れず、幅は埋まる。欠点: 箱を測るために、描画が 1 回やり直される。

## 結果

1280・1920・2560 で、タイムラインの幅は結果の幅と一致し、高さは画面の 45 % 以下になる。E2E の `layout.spec.ts` が確かめる。

小節の幅が例ごと・画面ごとに変わるので、絵の上の位置を固定の px で比べるテストは書かない（`layout.x` を使う）。
