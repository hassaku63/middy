# 0047. モードの和音に役割を付ける: 主和音・特徴和音・三全音の和音・そのほか

- 日付: 2026-11-10
- 状態: Accepted

## 文脈

機能（T・S・D）は、長調と短調の考え方である。モードでは成り立ちにくいので、画面（ADR-0045）と解説の文（ADR-0046）では、モードの和音を機能で呼ばないことにした。その結果、モードの和音を何で説明するかが空いた。所有者は #366 の C2（モードの役割をエンジンに足す）について、まず実現の見通しを評価し、見通しがあれば進めてよいとした。

モードの和声の教え方（Berklee の Ted Pease など。#366 のコメントに出典。原典は未確認）では、次の 3 点がほぼ共通している。

1. 各モードには特徴音がある。それを含む和音がモードらしく聞こえる。
2. 音階の三全音を含む和音は、同じ音でできた長調へ引き戻す。
3. 主和音へ戻る力は、特徴音が和音の根音にあるときがいちばん強い。

## 決定

- エンジン（`music`）は、モード（ドリアン・ミクソリディアン・フリジアン）の調の三和音に、度数から役割を付ける（`modalRole`）。
  - `tonic`: 1 度の和音。
  - `tritone`: 音階の三全音の 2 音を含む和音。
  - `characteristic`: 特徴音を含み、三全音を含まない和音。
  - `other`: それ以外。
  - 判定は音階だけから決まる。D ドリアンなら IV と ii が `characteristic`、vi° が `tritone`。G ミクソリディアンなら ♭VII と v、iii°。E フリジアンなら ♭II と ♭vii、v°。
- `Analysis.Role` と `DegreeChord.Role` に入れる。長調と短調、借用和音とセカンダリードミナントでは省く。`Analysis.Function`（ADR-0015）は変えない。
- 解説の文:
  - `characteristic` には「三全音を含まない特徴和音で、（モード）の響きをはっきりさせる。」を足す。特徴音が根音にあれば「主和音へ戻る力がいちばん強い」も足す。
  - `tritone` には、三全音の 2 音と同じ音でできた長調を名指しして、中心がぼやけると言う。特徴音の一文（「明るく聞こえる理由」）は付けない。
- 画面での使い方（地図を役割で並べる、札を役割の言葉にする）は、次のスライス（#366 の 2b）で入れる。

## 検討した選択肢

- 特徴和音を、モードごとに 1 つだけ表で決める（ドリアンは IV、ミクソリディアンは ♭VII、フリジアンは ♭II）: 決め方の根拠が言えず、ミクソリディアンの v のような和音を落とす。規則なら、どのモードでも同じ理由で決まり、リディアンなどを足すときも表が要らない。
- 終止の和音を役割に入れる: 主和音へ戻る力の強さは、特徴音が根音にあるかどうかの一文で言える。終止の判定（Modal）は今のまま使う。
- 七の和音や sus4 を、音そのものから判定する: 地図との一致を優先し、度数の三和音で判定する。

## 結果

- モードの例で、和音が「何をしているか」を、機能を使わずに言えるようになる。ミクソリディアンの特徴和音は ♭VII と v の両方で、♭VII のほうが主和音へ戻る力が強い、と規則から言える。
- API に追加の欄（`role`）が増える（省略可能なので、今の画面は壊れない）。
- 規則の出典はジャズの教え方が中心で、原典は未確認。ケルトやロックのモードでも同じ扱い（ドリアンの IV、ミクソリディアンの ♭VII）なので、食い違いは小さいと見ている。原典で確かめたら、この ADR に追記する代わりに新しい ADR で記録する。
