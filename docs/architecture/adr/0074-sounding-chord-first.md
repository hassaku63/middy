# 0074. 狭い画面では、今のコードの解説文を度数の地図より先に置く

- 日付: 2026-11-13
- 状態: Accepted（所有者の判断。#511 の 1 と 2。ADR-0044 の狭いときの並びと、ADR-0073 の決定 3 の特例を置き換える）

## 文脈

ADR-0044 は、解説を 2 つの群に分けた。
- 今のコードの群: 解説の枠。度数の地図と、1 和音の解説。
- 例全体の群: 解説のパネル。

結果の幅が広いとき（760 px 以上）は、解説の枠をタイムラインの上の帯にする。狭いときについては「今までどおり、どちらもタイムラインの下」とだけ決めていた。

枠の中は「地図が先、解説文が後」の順だった。そのため、狭い画面では、再生中に読むべき解説文が画面の外へ押し出されていた（#511 の計測）。
- PC 1024×768: 解説文がまるごと画面の外。
- スマホ縦 390×844: 解説文は 1 行目まで。

スマホ横（ADR-0073）だけは、特例で順を逆にしていた。

所有者は、解説の部品には表示の優先順位があると整理した（#511 の層）。
- 今のコードの見出しと解説文（層 1a）が最も高い。
- 度数の地図（層 1b）が次。
- 例全体の解説（層 2・3）は、はみ出してよい。

## 決定

1. **結果の幅が 760 px 未満のときは、解説の枠の中で、今のコードの見出しと解説文を先に、度数の地図を後に並べる。** CSS の `order` で並べ替え、部品の木は変えない（ADR-0042）。スマホ横の特例も、この規則に含まれる（右の列が、それ自身の `stage` として狭いため）。
2. **帯（760 px 以上）では、今までどおり、地図を左、解説文を右に置く。**
3. **画面の約束にする。** 再生中に結果の先頭を画面の上端に合わせたとき、どの画面でも、今のコードの見出しと解説文の先頭（2 行）が、タイムラインと一緒に画面に入る。E2E（`chord-frame.spec.ts`）で、1024×768、390×844、1280×800、820×1180 を確かめる。

## 検討した選択肢

- 解説文を先に、地図を後に（採用）。CSS だけで変えられ、ほかの部品の位置は変わらない。
- タイムラインの高さの上限を下げる。見本では、スマホ縦で絵が小さくなりすぎた。
- 解説の枠を画面の下に張り付ける。タイムラインの下を覆い、拡大表示では画面を占める。今は試さない（#511 の 5）。
- 枠を地図と解説文の 2 つに割る。ADR-0044 の「同時に読む」を捨てることになる。

## 結果

- 狭い画面でも、再生中に今のコードの解説が読める。地図は、その下にスクロールすると見える。
- DOM の順（地図が先）と見た目の順（解説文が先）が、狭い画面で異なる。読み上げとキーボードの順は地図が先のまま。地図の中には Tab で止まるものがないので、操作の順は変わらない。
- 再検討の条件: 地図を再生中に見られないことが不便だ、という声が出たとき。
