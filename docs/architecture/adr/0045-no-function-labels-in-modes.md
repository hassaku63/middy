# 0045. モードの例では、画面で和音を機能（T・S・D）で呼ばない

- 日付: 2026-11-10
- 状態: Accepted

## 文脈

機能（T・S・D）は、長調と短調の和声（機能和声）の考え方である。ドリアン・ミクソリディアン・フリジアンには導音がなく、D が主和音へ引き寄せるという前提が成り立ちにくい。ADR-0015 は、初学者向けの単純化として、モードの和音にも度数で機能を付けることにした。そのため、画面には次のような食い違いが出ていた。

- ドリアンの特徴和音 IV に「S・サブドミナント」の札が付く。
- フリジアンの ♭II（終止の役）が S の色になる。
- ミクソリディアンの v（引き寄せる力がない）が D の色になる。

ADR-0044 で、度数の地図を機能の列に並べるのは長調と短調だけにした。所有者は続けて、モードの例では機能の札と色も出さない案（案 B）を承認した。あわせて、モードの言葉で説明する本格的な対応を企画にした（#366）。

## 決定

- 画面は、例の調が長調か短調かを `isFunctional(mode)` で判定する。モード（ドリアン・ミクソリディアン・フリジアン）では、次の 3 つを出さない。
  - 1 和音の解説の機能の札（「S・サブドミナント」）
  - 読み上げの行の機能名（「IV G」だけを読む）
  - 度数の地図の機能の色（地図は度数の順。ADR-0044）
- 代わりに、地図の主和音（1 度）に形の印（枠の内側の輪）を付け、読み上げで「主和音」と名指しする。色に頼らない（WCAG 1.4.1）。
- エンジンの機能の割り当て（ADR-0015）と、解説の文は変えない。文の中の機能の言い方は #366 で扱う。

## 検討した選択肢

- そのまま（ADR-0015 の単純化を画面でも見せる）: モードで、間違ったことを札と色で言い続ける。
- 画面で T・S・D の代わりにモードの役割（特徴和音など）を出す: 役割の判定は音楽理論の判断で、エンジンに置くべきもの（ADR-0003）。#366 で扱う。
- 解説の文からも機能の一文を外す: エンジンの変更になる。#366 のスライス 1 として所有者の判断を待つ。

## 結果

- モードの例で、画面の札・色・読み上げが機能を名指ししなくなる。
- 解説の文には、まだ機能の言い方が残る（「IV（G）はサブドミナント（S）。」）。#366 が決まるまでの、既知の食い違いとする。
- 再検討の条件: #366 でモードの役割がエンジンに入ったら、この ADR の「出さない」を「役割で出す」に置き換える。
