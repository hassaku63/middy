# 0048. モードの地図を役割で分け、札と読み上げを役割の言葉にする

- 日付: 2026-11-10
- 状態: Accepted

## 文脈

モードの例では、機能（T・S・D）の札・色・読み上げを出さず、地図は度数の順に並べていた（ADR-0045）。エンジンは、モードの和音に役割（主和音・特徴和音・三全音の和音・そのほか）を付けるようになった（ADR-0047）。長調と短調では、地図を機能の列に並べ、札で機能を名指しする（ADR-0044）。モードでは、それに当たるものがなかった。

## 決定

- モードの例では、地図を役割の列に分ける。並びは、主和音 → 特徴和音 → そのほか → 三全音の和音。中心、モードらしさを作るもの、残り、中心をぼやかすものの順に読める。列には見出し（「主和音」「特徴和音」「そのほか」「三全音」）を付け、色では区別しない（WCAG 1.4.1）。列の間に矢印は付けない。機能の流れと違い、役割は進む向きを言わないから。
- 列の中は度数の順。和音の読み上げ名に役割を入れる（「IV（G）、特徴和音、この例で使う」）。主和音の印（ADR-0045）はそのまま。
- 1 和音の解説の札は、機能の代わりに役割の言葉にする（主和音・特徴和音・三全音の和音）。札は灰色で、色に意味を持たせない。「そのほか」の和音には札を付けない。
- 読み上げの 1 行（`ChordStatus`）も、モードでは役割の言葉を添える（「IV G 特徴和音」）。
- エンジンが役割を返さないとき（古い応答）は、今までどおり度数の順に並べる。

## 検討した選択肢

- 度数の順のまま、役割を色や印で示す: 列にすれば、どの和音が同じ役割かを見出しの言葉で一度に読める。色の対応表を覚えなくてよい。
- 機能の流れのように矢印でつなぐ: 役割は「次にどこへ行くか」を言わない。矢印は進行の向きを示すと読まれる。
- 「そのほか」の和音にも札を付ける: 札が言うことがない。度数は見出しの数字で見えている。

## 結果

- モードの例でも、和音が何をしているかを、画面の地図と札で機能を使わずに示せる。
- 地図の列の数が、モードでは 4、長調と短調では 3 になる。狭い画面でも、列は 2 段に折り返すので横にはみ出さない（E2E の `degree-map.spec.ts`）。
