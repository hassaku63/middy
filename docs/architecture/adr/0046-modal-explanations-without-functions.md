# 0046. モードの解説の文は、機能（T・S・D）を名指ししない

- 日付: 2026-11-10
- 状態: Accepted

## 文脈

ADR-0015 は、初学者向けの単純化として、モードの和音にも度数で機能を付けた。解説の文も、全モードで機能の一文から始めていた（「IV（G）はサブドミナント（S）。中心から離れて、動きを作る。」）。そのうえで、再検討の条件を置いていた。「モードごとの機能の説明が不十分だと分かったら、特徴音の一文を機能の置き換えに格上げする」。

機能は、長調と短調の和声の考え方である。モードには導音がなく、主和音へ引き寄せる力が成り立ちにくい。ADR-0045 で、画面の機能の札・読み上げ・地図の色はモードで出さないことにした。それでも、文だけは機能を名指しし続けていた。所有者は、#366 の C1（モードの文から機能の一文を外す）を承認した。

## 決定

- 長調と短調では、文は今までどおり機能の一文から始める。
- モード（ドリアン・ミクソリディアン・フリジアン）では、最初の一文を次のように置き換える。
  - 主和音: 「（モード）の主和音。調の中心で、落ち着いて聞こえる。」。主和音が中心で安定することは、モードでも成り立つ。
  - それ以外: 「（モード）の N 度の和音。」
- そのあとの文（特徴音の一文、フリジアンの ♭II の一文、終止の一文）は変えない。和音が何をしているかは、これらが言う。
- `Analysis.Function` は、ADR-0015 のまま度数で付ける。画面はモードではこれを出さない（ADR-0045）。

## 検討した選択肢

- 今のまま: 画面の札と色は機能を名指ししないのに、文だけが名指しして、食い違う。
- モードの役割（特徴和音・終止の和音）で文を組み立てる（#366 の C2）: 学習の面ではより正しい。ただし役割の判定を足す必要があるので、別のスライスで扱う。

## 結果

- モードの例で、画面と文のどちらも、和音を機能で呼ばなくなる。
- モードの主和音以外は、特徴音の一文がない和音（例: ドリアンの VII）だと、文が「ドリアンの 7 度の和音。」だけになり、情報が少ない。#366 の C2（役割）で補う。
- ADR-0015 の再検討の条件のうち、文についての部分を満たした。
