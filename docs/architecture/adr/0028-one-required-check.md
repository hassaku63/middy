# 0028. main の必須チェックは、`make check` に当たるジョブをまとめた 1 つだけにする

- 日付: 2026-11-09
- 状態: Accepted（所有者の判断は #219。ADR-0016 の決定 4 の集約ジョブを入れる。決定 4 の理由の「push で毎回走る」は ADR-0032 で変わった）

## 文脈

`main` のルールセット（`protect main`）は PR を必須にしているが、必須のステータスチェックがない。CI が赤のままでもマージできる。AGENTS.md の「`make check` が通らないものは完成ではない」は約束だけで、仕組みでは止めていない。マージするのは主に AI の session なので、仕組みで止めたい。

所有者は、次の条件で入れると決めた（#219）。

- PR の内容でスキップされるジョブが、マージを塞がない形にする。
- かなり保守的に、必須にする理由の強いものだけに絞る。

ADR-0016 の決定 4 は、その形を決めている。`skipped` を成功として扱う集約ジョブを 1 つ足し、それだけを必須にする。ジョブの `if` でスキップされたジョブは成功として報告されるが、`needs` の先が失敗すると下流もスキップされて成功に見える。集約ジョブが `needs.*.result` を見れば、この穴を塞げる。

## 決定

1. **`ci.yml` の `required (make check)` を、唯一の必須チェックにする。** 必須にするチェックの名前が 1 つなので、ジョブを足したり名前を変えたりしても、ルールセットは変えなくてよい。
2. **集約の対象は `changes`、`backend`、`frontend`、`docs`。** `make check` に当たるもの（整形、lint、テスト、ビルド、文書の検査）と、それを選ぶ `changes` だけにする。
3. **`success` と `skipped` は通し、`failure` と `cancelled` は落とす。** `if: always()` で、対象が失敗したときにも集約ジョブ自身は走る。
4. **`image` と `pr size budget` は対象にしない。** 理由は 2 つ。
   - `image` は外の配布元（ベースイメージ）に頼るので、関係のない不調で PR を塞ぎやすい。`main` への push では毎回走るので、壊れても気づける。
   - `pr size budget` は方針の検査で、所有者が例外を認めたい場面がある。ルールセットに例外にできる人がいないので、必須にすると所有者もマージできなくなる。
5. **`eval (real API)` と CodeQL も対象にしない。** 毎回は走らないか、外の不調で落ちる（CodeQL は、本体の配布の失敗 HTTP 504 で 2 回落ちた）。
6. **ルールセットの設定**:
   - `required_status_checks` には `required (make check)` を 1 つだけ入れ、`integration_id` は GitHub Actions（15368）にする。
   - `strict_required_status_checks_policy` は false にする（マージのたびに、ほかの PR すべての取り込み直しを求めない）。
   - 集約ジョブが `main` に入ってから設定する。逆の順にすると、集約ジョブのない PR が全部塞がる。

## 検討した選択肢

- A: 集約ジョブを 1 つ足し、それだけを必須にする。対象は `make check` に当たるもの（採用）。
- B: A に `image` と `pr size budget` も入れる。欠点: 外の不調による偽の失敗で PR が塞がり、サイズの例外を認める道もなくなる。
- C: 集約せずに各ジョブを必須にする。欠点: `changes` が落ちると下流がスキップされて成功に見える穴が残る。ジョブの名前を変えると、必須チェックが「Expected」のまま残る。

## 結果

- 整形・lint・テスト・ビルド・文書の検査のどれかが赤なら、マージできない。
- `image`・`pr size budget`・`eval`・CodeQL の赤では止まらない。PR を出す側が見る。
- ジョブを足すときは、`make check` に当たるものなら `required` の `needs` にも足す。
