# 0063. 評価のラベルは「何を走らせるか」と「絞り込み」で名前を分ける

- 日付: 2026-11-12
- 状態: Accepted（所有者の判断。ADR-0018・ADR-0038 のラベルの名前を置き換える）

## 文脈

実 API の評価は、PR のラベルで走る（ADR-0018）。ADR-0038 で、タグで絞る形（`needs-eval:<tag>`）を足した。そのあと BL-313 で、会話をまたいだ計測（`cmd/converse`）も同じジョブで走らせることにした。最初の案の名前は `needs-eval:converse` だった。

この形だと、`:` のあとに「ケースを絞るタグ」（meter、chords）と「別の種類の実行」（converse）が並ぶ。さらに `needs-eval` だけなら全件になる。所有者は、目で見て区別が付かず、ややこしいと指摘した。

## 決定

ラベルの名前は「`needs-eval-` のあとが何を走らせるか、`:` のあとが絞り込み」にする。頭の `needs-` は残す。ラベルは状態ではなく「CI でこれを走らせてほしい」という依頼で、走り終わるとジョブが外す。付いている間はまだ済んでいない、という読み方が実際の動きと合い、人が付けて人が読むラベル（`proposal` など）とも見分けられる（所有者の判断）。

| ラベル | 走るもの |
| --- | --- |
| `needs-eval-cases` | 評価のケースの全件と、独立したレビュアー |
| `needs-eval-cases:<tag>` | そのタグと smoke のケース（レビュアーは呼ばない） |
| `needs-eval-converse` | `cmd/converse` による会話の計測 |

絞り込みがあるのは `needs-eval-cases` だけにする。新しい種類の実行を足すときは、`needs-eval-<種類>` を足す。

## 検討した選択肢

- A: 種類を接頭に置く（採用）。利点: 何が走るかがラベルの頭で分かる。絞り込みは、それを持つ種類にだけ付く。欠点: 既存のラベルの名前が変わる。
- B: 絞り込みだけ別の接頭にする（`eval-tag:<tag>` と `eval:full`・`eval:converse`）。利点: 絞り込みかどうかが接頭で分かる。欠点: 全件と絞り込みが同じ「ケースの評価」だと、名前から読めない。
- C: 今のまま、文書で区別を説明する。利点: 変更がない。欠点: 名前を見ただけでは分からないまま。
- D: A から `needs-` を外す（`eval-cases` など）。利点: 短い。欠点: 依頼であること（まだ済んでいない）が名前から読めなくなる。

## 結果

- 評価のジョブ（`.github/workflows/eval.yml`）は、上の 3 つの形だけを受け付ける。ほかのラベルでは走らない。
- 前の名前（`needs-eval`、`needs-eval:<tag>`）では、もう走らない。リポジトリに残っている前のラベルは、所有者が消してよい。
