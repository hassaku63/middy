# 0036. シャッフルを、名前のついたノリとして足す

- 日付: 2026-11-10
- 状態: Accepted（所有者の判断は #308）

## 文脈

ノリ（`feel`）は `straight` と `swing` の 2 つだった。`swing` の長・短の比はテンポから決まり、遅いほど深く跳ねる（BL-084）。ジャズの傾向に合わせたもので、64 BPM では約 3 : 1 になる。

ブルースやロックの「シャッフル」は、8 分音符を 3 連符の 1 つ目と 3 つ目で弾く。長・短の比は 2 : 1 で、テンポによらない。評価では、blues-shuffle のケースが毎回「12/8 のシャッフル」を「表せないもの」に挙げていた（#308）。

エンジンには、比と音価を指定して揺らす仕組みがもうある（`pattern.Swing`、BL-084）。足りないのは、それを選ぶ入口だった。

## 決定

1. **ノリに `shuffle` を足す。** 8 分音符の組を、比 2 : 1（3 連符の 1 つ目と 3 つ目）で揺らす。テンポによらない。中身は今の揺らしの仕組みで、比を固定するだけ。
2. **`swing` は今のまま**（比はテンポから決まる）。両者の違いは、解説の文で述べる。
3. **`swing` と同じく、6/8 では使わない**（拍がすでに 3 つに分かれている）。エンジンとインテントが拒む。
4. **スタイルでは、pop・rock・jazz のノリの一覧の末尾に足す。** スタイルのグルーヴ（一覧の先頭から選ぶ）は変わらない。
5. **契約**：`openapi.yaml` の `Feel` の enum に `shuffle` を足す。インテントの enum はカタログから作られるので、自動で増える。
6. **12/8 の拍子は、今は足さない。** シャッフルで足りるかを評価で見てから決める（#308）。

## 検討した選択肢

- A: 名前つきのノリ `shuffle`（採用）。利点：入口を 1 つ足すだけで済み、学ぶ人にも「シャッフル」という名前で見せられる。欠点：`Feel` の enum が増える。
- B: AI に比を数値で書かせる。欠点：数値の意味を学ぶ人に説明しにくく、AI に音の細部を書かせることになる（ADR-0003 の境界に近づく）。
- C: 12/8 の拍子を足す。利点：譜面のうえでも正しい。欠点：拍子の一覧、API、プロンプト、フロントの改修が要り、大きい（ADR-0017 の改訂）。

## 結果

- 「タッカ・タッカ」のシャッフルを、テンポによらず鳴らせる。
- 16 分のスウィング（`swing-16`）は、同じ仕組みで足せる。ただし、深さの既定値をどう決めるかの判断が要るので、別にする。
