# 0065. 頼まれたものを採り入れる程度には幅を認め、計測は答え単位で数える

- 日付: 2026-11-12
- 状態: Accepted（所有者の判断。Issue #473）

## 文脈

middy は作曲の初心者のためのアプリで、AI は依頼を例（候補）に解釈する。依頼には、どの程度採り入れるかの解釈の余地がある。

- 「テンションコードを使って」に、1 か所だけ入れるのか、全体に入れるのか。
- 「sus と add を使って」のように複数を挙げたとき、全部使うのか、一部でよいのか。
- 初心者向けに、和音や進行をやさしくすること。

会話の計測（`cmd/converse`）は、台本の期待を例ごとに ✓／✗ で数えていた（BL-314）。期待は「すべての例が、挙げた語をすべて含むか」だった。そのため、一部の例や一部の語だけを採った答えが ✗ として並び、「まったく採っていない」と見分けられなかった。

会話の査読（ADR-0064）は、指示で幅を認めて数えなくした。ただ、数えなかったものが出力に残らなかった。

## 決定

1. **プロダクトの方針として、採り入れる程度には幅を認める。** 次は「依頼に従っていない」としない。
   - 程度の違い（1 か所だけか、全体か）。
   - 複数挙げたうちの一部だけ。「全部使って」と明示されていても、一部ならよい。
   - 初心者向けの意図的な単純化。

   拍子や小節数のように数で言える依頼も同じに扱う。アプリの AI へのプロンプトは、この ADR では変えない。
2. **「採っていない」は、答えのどの例にもまったく入っていないときだけ。** 計測は答え単位で数える。期待ごとに、採った例の数（k/n）と、✓（すべての例）・△（一部の例。幅の内）・✗（どの例も採っていない）を出す。△ は失敗ではない。
3. **台本の期待は、幅に合わせて書く。** 語ごとの `has` に加えて、どれか 1 つでよい `hasAny` を使う。たとえば「ii–V–I を」には `hasAny: ["ii7", "iiø7", "V7"]` を使い、七の和音を全例に求めない。
4. **幅の内は、見せるが数えない。** 査読（ADR-0064）も、幅の内として数えなかったものを一覧で見せる（BL-322）。幅が何を通しているかを、所有者が読めるようにする。
5. **幅そのものを見る台本を 1 本置く**（`scenarios/tolerance.json`）。頼み方を「テンションを使って」から「全部使って」へ強めていく。

## 検討した選択肢

- A: 答え単位で 3 段階と k/n（採用）。利点: 幅の内（△）と採っていない（✗）が分かれる。k/n が残るので、全例から 1 例への後退も見える。欠点: 例ごとの ✓／✗ の列はなくなる（事実の列は残る）。
- B: 例ごとの ✓／✗ のまま、読み方を文書に書く。利点: 変更がない。欠点: ✗ が幅の内か外かを、行を数えないと読めない。
- C: 採った／採っていないの 2 値だけ。利点: 最も単純。欠点: 1/3 と 3/3 が同じに見え、後退に気づけない。
- D: 「全部」と明示されたときだけ厳しくする（`hasAll`）。利点: 指示の強さに合う。欠点: 所有者が「全部」もゆるめてよいとした。要るときに足す。

## 結果

- 計測の ✗ は「まったく採っていない」だけになる。
- 部分一致の限界: 三和音だけの ii–V–I は `hasAny` でも拾えない（`ii` は `iii` にも当たる）。並びの確かめは査読に任せる。
- アプリの AI にこの幅をどう伝えるか（伝えるべきか）は、計測の結果を見てから考える。
