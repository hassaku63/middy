# 0058. 配置の E2E を、フロントエンドを変える PR の必須の検査に入れる

- 日付: 2026-11-11
- 状態: Accepted（ADR-0028 の必須の検査の対象を広げる）

## 文脈

画面の幅による配置の崩れは、単体テストでは見えない。これまで E2E は、手動と週次（`e2e.yml`）だけで走っていた。崩れても、マージのあとでしか気づけなかった。

配置の規則（ADR-0042）は、幅で操作を失わないこと、窓の大きさを変えても状態を保つことを求めている。ところが、それを確かめる検査がなかった。

所有者は、決定的な配置の検査だけを、フロントエンドを変える PR の CI で走らせることにした（#359 の C）。画像による UI レビューは、引き続き CI に入れない。

## 決定

- 画面サイズの行列を `frontend/e2e/sizes.ts` の 1 つにする。ui-review の撮影（`ui-shots.spec.ts`）も同じ行列を使う。
- `e2e/sizes.spec.ts` が、行列のすべてのサイズで次の 4 つを確かめる。
  - ページが横にスクロールしない。
  - axe の違反がない。
  - 結果の操作（ボタン、選択）の集合が 1280 と同じ。
  - 窓の大きさを変えても、固定した和音が残る。
- CI の `layout` ジョブが、フロントエンドを変えた PR でこれを走らせる。
  - Go のサーバー（fake の LLM）と、`/api` をプロキシする `vite preview` で動かす。
  - コンテナイメージとレジストリには頼らない。ADR-0028 が `image` を必須から外した理由（外の不調で PR を塞ぐ）を避けるため。
- `layout` を `required (make check)` の対象に入れる。

## 検討した選択肢

- A: `image` のジョブ（compose の本番相当のスタック）で走らせ、`image` を必須にする。欠点: ベースイメージの配布元の不調で PR が塞がる（ADR-0028）。
- B: 週次のまま。欠点: 配置の崩れがマージのあとでしか見つからない。
- C（採用）: イメージなしの別のジョブで、決定的な検査だけを必須にする。

## 結果

フロントエンドを変えた PR は、5 つのサイズで配置の検査を通らないとマージできない。CI は数分長くなる（Chromium の導入とビルド）。

nginx の配信の規則（キャッシュ、CSP）は、この検査の対象外。引き続き `image` のスモークと週次の E2E で確かめる。
