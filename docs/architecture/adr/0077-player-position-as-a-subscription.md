# 0077. 再生位置は購読する値にし、描く部品だけが読む

- 日付: 2026-11-13
- 状態: Accepted（#500 のスライス 4）

## 文脈

`usePlayer` は再生位置を `useState` に持っていた。プレイヤーは再生中に 1 秒に何度も位置を知らせるので、そのたびに `App` 全体が描き直されていた。描き直しの範囲には、会話の列、プロジェクトの一覧、ツールバーの調や型の選択も入る。#500 の監査では、再生中のメインスレッドの使用が 1 秒あたり約 128 ms、CPU を 6 倍遅くすると約 798 ms あった。

位置を見せるのは、ツールバーの位置の表示と、ステージ（タイムライン、和音の枠、解説）だけである。

## 決定

1. 再生位置は `App` の状態にしない。`usePlayer` は `position`（`get` と `subscribe` を持つ値。`features/player/position`）を返す。
2. 位置を描く部品だけが `usePosition(player.position)`（`useSyncExternalStore`）で読む。今は `PlayerControls` と `app/Stage`。
3. `App` は、再生の状態（再生中・停止）が変わったときだけ描き直す。単体テストで、再生中に会話の列が描き直されないことを確かめる。
4. 状態管理ライブラリは入れない。購読する値は 30 行の自前の部品で足りる。

## 検討した選択肢

- 購読する値と `useSyncExternalStore`（採用）。React の標準の API で、依存を足さない。
- context で位置を配る。context の値が変わると、それを読む部品は描き直されるが、配る側の `App` の描き直しは減らない。位置を読む部品を context の下に分ける必要もある。
- `React.memo` で `App` の子を 1 つずつ止める。止める部品が増えるたびに props の同一性を保つ手当てが要り、漏れても気づきにくい。
- 状態管理ライブラリ（Zustand など）。依存の追加になる（AGENTS.md）。この 1 つの値のためには要らない。

## 結果

- 再生中に描き直すのは、ツールバーの位置の表示とステージから下だけになる。
- ステージの中の動かない部分（ピアノロールの音符、和音の枠の文など）は、まだ毎回描き直す。#500 のスライス 5 で memo にする。
- 位置を新しく見せる部品は、`usePosition` で読む。`App` の状態に戻さない。
- 再検討の条件: 位置のほかにも、再生中に速く変わる値を複数の部品が読むようになったとき。
