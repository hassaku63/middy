# 0041. 広い画面の上限: 横幅 2560 px とタイムラインの高さ 45 %

- 日付: 2026-11-10
- 状態: Accepted（タイムラインの縦横比は ADR-0057 が置き換えた）

## 文脈

wide の配置（#279）は、1024 px 以上で会話を左の列に、結果をその右に置く。結果の中では、タイムラインを横いっぱいに描き、その下に解説を並べる。ページ全体の幅は 1440 px で止めていた。そのため、1920 px や 2560 px の画面では、左右に大きな余白が残った。止めずに広げると、今度はタイムラインが縦横比を保ったまま高くなる。すると、再生中に、鳴っている和音の解説の枠が画面の下に押し出される（#353）。

画面の約束（`docs/product/experience.md`）は、再生中にタイムラインと鳴っている和音の解説が同時に見えることを求める。

## 決定

- 1024 px 以上の配置で、ページの横幅の上限を 2560 px（QHD）にする。所有者が賛同した（#353）。これより広い画面では中央に寄せる。
- 結果の中のタイムラインは、高さを画面の 45 % までにする。縦横比は保つ。上限に当たると、タイムラインの幅は結果の幅より狭くなり、左に寄る。縦横比はタイムラインの SVG が CSS 変数 `--timeline-aspect` として渡す。CSS はそれを使い、`max-width: calc(45vh * var(--timeline-aspect))` で幅を止める。
- 解説の 1 行は 40 字まで（WCAG 1.4.8 の CJK の上限。#353 のスライス 2）。

## 検討した選択肢

- A: 上限なしで、画面の幅を使い切る。利点は余白がないこと。欠点は、2560 px を超える画面で 1 行が長くなり、目の移動が増えること。所有者は「無制限に使い切る必要はない」と判断した。
- B: 上限 1920 px で中央に寄せる。利点は配置が安定すること。欠点は、2560 px の画面で 640 px が余ること。
- C: タイムラインの高さを止めず、解説の枠を画面の下端に固定する。欠点は、枠がタイムラインの一部を覆い、重なりの管理が要ること。
- D: SVG の `preserveAspectRatio` で描画だけを縮め、箱は結果の幅のままにする。欠点は、背景の帯が左右に残り、タイムラインの範囲がわかりにくいこと。

## 結果

- 1920×1080 と 2560×1440 で、再生中にタイムラインと 1 和音の解説の枠が同時に画面に入る。E2E の `layout.spec.ts` が確かめる。
- 広い画面では、タイムラインの右に余白が出る。解説を右の列に置く案（B、#353 のスライス 4）は、所有者が画像を見て決める。
- 再検討の条件: 2560 px を超える画面で使う人が出たとき。高さ 45 % で和音の名前が読みにくいという報告が出たとき。
