# 0016. CI は、アプリと同じ版をキャッシュで速く取り、検査を 1 回ずつ走らせ、差分でジョブを選ぶ

- 日付: 2026-11-08
- 状態: Accepted（所有者の判断は Issue #98。決定 4 の集約ジョブは ADR-0028 で入れた）

## 文脈

PR の CI は約 3.5 分かかり、律速は `backend (Go)` だった。その半分以上は、テストではなく準備に使われていた（測定は #98）。

- Go 1.25.0 を毎回ダウンロードしていた（`.tool-versions` の版がランナーのプリインストールの patch と違う）。
- `setup-go` のキャッシュが無効で、`go vet` と race 付きテストが毎回コールドにコンパイルしていた。テスト自体はほぼ 0 秒。
- golangci-lint のバイナリを GitHub のリリースから毎回取り、その配布の 504 でジョブが落ちていた（#97）。
- `dependency hygiene` ジョブが、3 秒の検査のために Go をもう一度取得していた。所要時間のレポートは、テストスイートをもう一度実行していた。
- 直近 60 件の変更のうち 38 件は backend に、33 件は frontend に触れていないのに、毎回 6 ジョブすべてが走っていた。

リポジトリは public で、Actions の課金はない。問題は費用ではなく、PR を待つ時間と、外部の配布の不調による偽の失敗である。所有者の判断（#98）: CI の版はアプリの実装が使う版に揃える（版の更新は別に検討する）。`main` への直接 push は禁止で、必須チェックは今は意図的に外している。

## 決定

1. **版は `.tool-versions` のまま。取得の費用はキャッシュで払う。** ランナーのプリインストールの版には合わせない（ADR-0008 の「版は 1 か所」を保ち、CI と配備の版をずらさない）。
   - Go 本体: ランナーのツールキャッシュの該当ディレクトリを `actions/cache` で版ごとに保存し、`setup-go` が手元で見つけるようにする。
   - Go のモジュールとビルド: `setup-go` のキャッシュ（キーは `backend/go.sum`）。
   - golangci-lint: バイナリを `actions/cache` で版ごとに保存する。取りに行くのはキャッシュがないときだけで、`scripts/install-golangci-lint.sh` が再試行とチェックサムの検証つきでリリースから取る。リリースが取れなければ、同じ版をモジュールプロキシからビルドする（ビルドに使う Go は、プロジェクトの版に固定する）。
2. **すべてのジョブに `timeout-minutes` を付ける。** 既定の 6 時間のまま、ハングしたジョブが残らないようにする。
3. **同じ検査を 2 回走らせない。** `go mod tidy -diff` は backend ジョブ、`npm audit --omit=dev` は frontend ジョブで走らせ、`dependency hygiene` ジョブはなくす。所要時間のレポートは、同じテストの実行が書いた JSON から作る。`make check` と `make deps-check` の中身は変えない。
4. **差分でジョブを選ぶ**（BL-096 で実装する）。パスのフィルタを 1 か所に定義し、各ジョブの `if` で使う。ワークフロー全体の `paths:` フィルタは使わない。`image` ジョブは、PR では Dockerfile・backend・frontend に触れたときだけ走らせ、`main` への push では毎回走らせる。必須チェックがない間は集約ジョブを置かない。必須チェックを入れるときに、`skipped` を成功として扱う集約ジョブを 1 つ足し、それだけを必須にする。

## 検討した選択肢

- **ランナーのプリインストールの Go に合わせる**（`.tool-versions` を月ごとに上げる）: ダウンロードは消えるが、アプリの版がランナーの都合で動く。所有者の判断で採らない。
- **golangci-lint を常にモジュールプロキシからビルドする**（`install-mode: goinstall`）: リリースの配布に依存しないが、action の README が推奨していない。キャッシュがないたびに 30〜45 秒かかる。代わりの経路としてだけ使う。
- **テストの分割・並列化、影響を受けたテストだけを走らせる、PR で `-race` を外す:** 費用はコンパイルで、テストの実行ではない。キャッシュで解決し、検出力は落とさない。
- **ワークフロー全体を `paths:` で絞る:** 必須チェックを入れたときに、走らなかったチェックが「Expected」のまま残ってマージを塞ぐ。ジョブ単位の `if` にする。
- **何もしない:** 外部の配布の 504 による偽の失敗が続き、「CI が赤いのが普通」という慣れを生む。

## 結果

- 2 回目以降の実行は、Go、golangci-lint、モジュール、ビルドをキャッシュから取る。GitHub のリリースの配布が不調でも、キャッシュがあれば CI は落ちない。
- キャッシュは 1 リポジトリ 10 GB まで、7 日使われなければ消える。Docker の `type=gha`（`mode=max`）と同じ枠を使う。版を上げた直後の初回だけはコールドになる。
- 外部からダウンロードするものと、その代わりの経路は `docs/dev/harness.md` に一覧する。
- 再検討の条件: キャッシュの枠があふれて退避が目立つとき（`mode=max` を見直す）。必須チェックを入れるとき（決定 4 の集約ジョブ）。フィルタの漏れで偽の緑が出たとき（フィルタの経路の表を直し、漏れた経路をテストで固定する）。
