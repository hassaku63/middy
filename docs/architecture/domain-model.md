# ドメインモデル

音楽理論の語彙を、コード上の型に対応づける。**ここに書かれた定義が `backend/internal/music` の仕様** であり、テストはこれを根拠にする。曖昧な点があれば、実装より先にこの文書を直す。

## 規約

| 項目 | 規約 |
| --- | --- |
| ピッチ | MIDI ノート番号 0..127。**C4 = 60**（middle C） |
| ピッチクラス | 0..11、C = 0。調に依存しない表示（`String()`）はシャープ。調の中での綴りは `Key.PitchClassName` / `Key.ChordSymbol`（B♭ major では `Bb`、`Bbmaj7`）。親となる長調の調号から決め、同数なら ♭ |
| 時間 | tick。`DefaultPPQ = 480`（四分音符 = 480 tick） |
| 度数 | 1 始まり（1 = 主音, 5 = 属音） |
| チャンネル | 0 始まり。9 = GM パーカッション |
| プログラム | GM プログラム番号 0 始まり（0 = Acoustic Grand Piano） |

## 型

### 音高

- `PitchClass` — `Normalize()`, `Add(semitones)`, `String()`, `FlatName()`
- `Pitch` — `NewPitch(pc, octave)`, `Valid()`, `Class()`, `Octave()`, `Transpose()`, `String()`（`"C#4"`）

### 調と音階

- `Mode` — `Major`, `Minor`（自然短音階）, `Dorian`, `Mixolydian`（ADR-0015）。JSON では `"major"` / `"minor"` / `"dorian"` / `"mixolydian"`。ローマ数字はそのモードの音階に対して書く（D ドリアンは `i ii III IV v vi° VII`、G ミクソリディアンは `I ii iii° IV v vi VII`）。質は音階から導くので、モードを足すのは `modeIntervals`・`parentOffset`（綴り）・`characteristicDegree`（解説）の 3 行。`Characteristic()` はモードの特徴音の度数（ドリアン 6、ミクソリディアン 7。長調・短調は 0）
- `Key{Tonic, Mode}` — `Scale()`（7 音）, `Degree(n)`, `Contains(pc)`, `Diatonic(degree, seventh)`

### コード

- `ChordQuality` — 三和音 4 種（maj, min, dim, aug）、七の和音 4 種（maj7, min7, dom7, m7b5）、六の和音 1 種（min6。長調で借用する ivm6 のため）。JSON は識別子文字列（`"dom7"`）
- `Chord{Root, Quality}` — `PitchClasses()`, `Voicing(octave)`（密集・基本形）, `String()`（`"G7"`）
- `RomanNumeral(degree, quality)` — `I`, `ii`, `vii°`, `V7`, `iiø7`, `IVmaj7` など。大文字 = 長/増、小文字 = 短/減。`RomanNumeralAlt(degree, accidental, quality)` は根音を半音下げた `♭VI`, `♭VII7` も書く
- 長調の借用の範囲外でも、♭ 付きのラベルを主音からの距離で読んだ和音（`LiteralChord`）がその調の和音と同じなら、受け付けて調の表記にそろえる（ミクソリディアンの `bVII` は `VII`、短調の `bVI` は `VI`。#109）。音は書いたとおりなので、黙って直すことには当たらない。同じにならないもの（短調の `bII`）は落とす
- `LiteralChord(tonic, label)` — ラベルを、調に関係なく、主音の長音階に対して書いたとおりに読む（大文字・小文字と接尾辞が質、先頭の ♭ / b が根音を半音下げる）。`bVII` は主音の全音下の長三和音。評価の `wants` のように「どの調でも同じ響き」を指すときに使う
- `ParseRomanNumeral(s)` — 上記の表記（と `dim`, `aug`, `+`, `m7b5`）を度数と七の和音の有無に戻す。`RomanNumeral` の出力は必ず往復する。大文字・小文字の違いは `StepFromLabel` だけが（短調の V で）使う

**未対応（backlog）**: テンション、承認済みのセット以外の借用和音（長調の ♭II・♭III、短調の七の和音の借用など）、V 以外を当てる和音（`vii°/x` など）。

### タイムライン

```
Timeline
├── PPQ, TempoBPM, TimeSignature, Key
├── Tracks[]            楽器レーン
│   └── Notes[]         NoteEvent{Pitch, Velocity, Start, Duration}
└── Harmony[]           HarmonyEvent{Start, Duration, Chord, RomanNumeral, Analysis?}
```

- `Timeline` は **再生・描画・解説・書き出しのすべてが消費する唯一の成果物**。
- `Harmony` は音を出さない注釈。解説レイヤー（和声機能、ケーデンス）はここに情報を足す。
- `Validate()` は API 境界で必ず呼ぶ。内部の関数は妥当な Timeline を前提にしてよい。
- `LengthTicks()` は最後のノート／注釈の終端。
- `TempoBPM` は拍子の拍が 1 分に何回か（4/4・3/4 では 4 分音符、6/8 では付点 4 分。ADR-0019）。秒や MIDI のテンポは 4 分音符で数えるので、`QuarterBPM()` で換算する（6/8 の 60 は 90）。

### 進行

- `Step{Degree, Seventh, Beats, Quality?, Bass?, Push?}` — 度数（1..7）を何拍鳴らすか。拍は拍子の拍（ADR-0017。`BeatTicks`）。`Bass{Degree, Accidental}` は分数コードのベース（ADR-0020）で、ラベルでは `/` のあとに調の度数を数字で書く（`I/3`、`IV/1`、`i/#7`。`/` のあとがローマ数字ならセカンダリードミナント）。ベースは和音の下（オクターブ 3）で鳴り、`HarmonyEvent.Bass` に入り、和音名は「C/E」と綴る。伴奏の型の `bass` 声部はそのベースを弾く。ベースの声部を持たない型では、分散和音は `root` の代わりにそのベースから始め、それもない型（`block`、`strum`、`drone` など）は和音の下にベースを足す。どの型でも分数コードのベースが鳴る（`drone` では主音の持続がさらに下にある）。和音自身の根音をベースにしたラベル（`I/1`）は基本形として読み、分数コードにしない。解説は、ベースが和音の音なら転回形（3 度・5 度・7 度。`ivm6` の 6 度は「足した 6 度」と呼び、7 度とは呼ばない）、和音にない音で隣と同じならペダル、前後のベースのあいだにあるなら経過音と述べる（転回形でも隣と同じベースならペダルとしても働くと添える）。例全体の流れは、分数コードを含んで 3 つ以上の和音のベースが順に動く区間を名指しし、同じ和音のままベースが半音ずつ動くならライン・クリシェと呼ぶ。分析はラベルの分数コードの `/` をセカンダリードミナントの `/` と取り違えない。`Quality` は根音を保ったまま質を上書きする（今は短調の V のためだけに使う）。`Push` は押し（BL-121）で、和音を拍の頭より 8 分（`eighth`）か 16 分（`sixteenth`）早く弾いてつなぐ。最初の和音には付けられない。`HarmonyEvent.Push` に残り、`Start` は和音が属する拍のまま（小節の数え方は変わらない）。`PushNotes` が、`Start` で鳴る音をその分早めて伸ばし、前の和音の音を押しの位置で切る。伴奏の型はノリより先に押しを掛けるので、押した 8 分もスウィングする。解説は「8 分音符ひとつ早く（2 拍目の裏で）入る（押し）」と述べる
- `StepFromLabel(key, label, beats)` — ローマ数字の文字列から `Step` を作る唯一の入口（API と intent が使う）。短調の大文字 `V` / `V7` を和声的短音階のドミナントにする規則はここにある
- `Progression []Step` — 調に依存しない進行テンプレート。`Validate()` は全ステップの問題をまとめて返す
- `FromProgression(key, prog, tempoBPM)` — 進行を調で解決し、ブロックコード 1 トラック（GM ピアノ, ch.0, `ChordVelocity`=80）と `Harmony` 注釈を持つ `Timeline` を返す。和音は `LeadVoicings` で前の和音から声部の動きが最小になるように置く（BL-086）。最初の和音は `ChordOctave`=4 の密集した基本形、次からはその和音の転回形のうち最低音が C4〜B4（最初の和音の基本形と同じ範囲）に入るもので（オクターブ 3 のベースが必ず和音の下になる）、声部の動き（同じ数の音なら声部ごとの半音の差の和、違えば各音から最も近い前の音までの和）が最小のもの。同点なら最低音が中央の C に近いもの。ii7–V7–Imaj7 では上声が半音か全音ずつ動く。リズム・ボイシングのパターンはこの上に重ねる（BL-020, 021）
- `FromProgressionIn(ts, key, prog, tempoBPM)` — 同じことを別の拍子で行う（4/4、3/4、6/8。ADR-0017）。`Step.Beats` は拍子の拍で数える（4/4 と 3/4 では 4 分音符、6/8 では付点 4 分。`BeatTicks(ts, ppq)`）。6/8 のような複合拍子（`TimeSignature.Compound()`）は、拍が 8 分音符 3 つに分かれ、1 小節を 2 拍と数える（`BeatsPerBar()`）。`FromProgression` は 4/4 のこれ

### 分析（解説データ）

- `Function` — `T` / `S` / `D`。度数で決まる: I, III, VI = T、II, IV = S、V, VII = D。長調・自然短音階とも同じ割り当て（短調の v と VII は「弱いドミナント」扱い。VII は下の段落のとおり隣の和音で働きを言う。借用和音は、その度数の機能をそのまま使う: iv は S、♭VI は T、♭VII は D）
- `Cadence` — 直前のコードからの進行の分類: `authentic`（V→I）、`plagal`（IV→I）、`half`（V 以外→V）、`deceptive`（V→vi）、`modal`（ドリアン・ミクソリディアンの VII→I。導音を使わない）。該当なしは空。`authentic` / `deceptive` / `half` の V は、導音を持つ V（長三和音か属七）に限る。自然短音階・ドリアン・ミクソリディアンの短三和音の `v` からの進行には、終止の名前を付けない（ADR-0012 の判断 2）
- 短調の `VII` は、隣の和音で働きを言う（ADR-0012 の判断 2）: 次が `III` なら III の V にあたる働き（V/III）、次が `i` なら導音のない弱いドミナント、`i` と `VI` のあいだなら V へ下りる線の途中（経過）。機能の印は度数どおり D のまま、解説の一文で補う
- 長調以外では、根音が長音階の同じ度数より半音低い和音に、長音階から見た呼び名を解説で添える（ミクソリディアンの `VII` は ♭VII、短調の `VI` は ♭VI。#130）。ローマ数字そのものは調の音階に対して書く（ADR-0015）。
- `Overview{Whole, Flow, Degrees}` — `Timeline.Overview` に付く例全体の解説で、`Analyze` が最後に作る（BL-098）。全体は、モードとその性格に加えて、ドリアンとミクソリディアンでは特徴音を含む和音と、比べる相手のモード（ドリアンは短調、ミクソリディアンは長調）ならその位置が何になるかを名指しする。長調では借用和音、短調では和声的短音階の V を名指しする。流れは、和音の数と小節数、始まりの和音、最後の終止、繰り返したときに頭へ戻る終止を言う。`Degrees` は度数の地図（BL-099）で、調のモードの三和音 7 つ（`DegreeChord{Degree, RomanNumeral, Symbol, Function, Used}`）。機能は個別の解説と同じ割り当て。`Used` は、例がその度数を調の和音として鳴らすとき（七の和音や短調の V を含み、借用和音とセカンダリードミナントは含まない）
- 解説（ここに書く `Explanation` と、AI が書く文）で何を誤りとし、何をゆらぎとして許すかは ADR-0034。
- `Analysis{Degree, Function, Cadence, Explanation}` — `HarmonyEvent.Analysis` に付く。`Explanation` は UI にそのまま出せる日本語で、決定論的に組み立てる（LLM は使わない）。機能（T/S/D）は全モードで度数から付ける初学者向けの単純化。モードの特徴音を含む和音には、その音を名指しして「なぜそう聞こえるか」の一文を足す（ADR-0015）
- `Analyze(Timeline) (Timeline, error)` — 入力を変更せず、`Harmony` に `Analysis` を付けた複製を返す。ダイアトニックでも長調の借用和音でもないコードがあればエラー。借用和音には `Borrowed: true` を付け、解説に「同主短調（C minor）から借りた和音」の一文を足す

### 書き出し

- `smf.Write(Timeline) ([]byte, error)`（`internal/music/smf`）— Standard MIDI File format 0。テンポ・拍子・調号のメタイベント（調号は親の長調のもの。ドリアンやミクソリディアンも、画面と同じく ♭6 つの調は ♭ で書く）、トラックごとのプログラムチェンジ、ノートのオン／オフを 1 トラックに統合する。同一 tick ではオフ → オンの順（同じ音の連打を正しく切る）。`Analysis` やトラック名は含まれない

### 音楽的意図（`internal/intent`）

- `intent.Intent{Summary, Mood, Candidates}` — LLM が 1 ターンで返す構造化の答え。`Summary` は返答文、`Mood` はタグ、`Candidates` は 1〜3 個の提案
- `intent.Candidate{Title, Key, TempoBPM, Progression, BeatsPerChord, Beats?, Pushes?, Reason, Accompaniment?, Drums?, DrumGrid?, Feel?, Meter?}` — エンジンが描画できる具体案。`Progression` はローマ数字の文字列（`ParseRomanNumeral` の語彙）、`Meter` は `4/4`（省略時）・`3/4`・`6/8`（ADR-0017）、`Beats?` は和音ごとの長さ（BL-109。`Progression` と同じ数。1 小節より短い和音は小節を等分した位置から、1 小節以上は小節の頭から始め、合計は小節の切れ目で終える。省略時は全部が `BeatsPerChord`）、`Pushes?` は和音ごとの押し（BL-085。`none` / `eighth` / `sixteenth` を `Progression` と同じ数。最初の和音は `none`）、`BeatsPerChord` は拍子の拍の数で 4/4 なら 1 / 2 / 4 / 8、3/4 なら 3 / 6（1 小節か 2 小節）、6/8 なら付点 4 分で 1 / 2 / 4（半小節・1 小節・2 小節）、`TempoBPM` も拍子の拍で数える（ADR-0019）、伴奏とドラムはその拍子の型だけ、6/8 では `Feel` に `swing` を使わない、`Accompaniment` / `Drums` はパターンカタログの id、`DrumGrid` は `Drums` の代わりに書く格子（BL-077。`basedOn` はその拍子とスタイルのドラムの id）、`Style` はスタイルの id（`Validate` が型とノリとの整合を検査する。BL-082）、`Feel` は 8 分音符のノリ（`straight` / `swing`。`Schema` の enum とシステムプロンプトの一覧はカタログから生成される）
- 綴り（`spelling.go`）: 調の親となる長調（短調は主音から長 6 度上。モードを足すときは `parentOffset` に 1 行）の主音の綴りを表で決め、その音階を 7 つの文字に乗せる。ダイアトニックな音は文字で、それ以外は調の側（♭ の調なら ♭）で綴る。`HarmonyEvent.Symbol` と解説文はこれを使い、画面は `symbol` をそのまま出す（`keyName` の表だけフィクスチャで一致を検査）
- `Validate()` が全問題をまとめて返す（テンポ 40〜220、進行 1〜16 個、ローマ数字の妥当性など）。ラベルの書き方（大文字・小文字、7 の種類）が調から決まる和音と食い違うもの（短調の `II`、長調の `Vmaj7`）は、`music.CanonicalLabel` が「何として鳴るか」と正しい表記を添えて落とす。黙って直さない（ADR-0013）。`Parse` は通ったラベルをエンジンの表記にそろえる（`iim7b5` → `iiø7`）。`Schema` は同じ制約を LLM に伝えるが、構造化出力が受け付ける JSON Schema のサブセット（`maxItems` や `minimum` / `maximum` は不可）で書けない上限は説明文で伝え、`Validate` が最終判定する（サブセットの遵守は `TestSchemaUsesOnlySupportedKeywords` が検査）。`Parse(data)` は復号と検証
- `Candidate.ToProgression()` で `music.Progression` に変換し、`FromProgression` → `Analyze` の既存経路に乗せる

### パターン（`internal/music/pattern`）

- `pattern.Accompaniment{ID, Name, Description, Program, Meter, Hits}` — 1 小節（`DefaultPPQ`）の伴奏テンプレート。`Meter` はその型が書かれた拍子で、`nil` はどの拍子でも使える（`block`。`Duration` 0 は小節の終わりまで）。`Hit{Start, Duration, Voice, Velocity}` の `Voice` はコードの密集ボイシングに対する相対指定（`chord` / `bass` / `root` / `third` / `fifth` / `top` / `octave`）。`chord` と `top` は前の和音から導いたボイシング（`LeadVoicings`）を、分散和音の声部は基本形を使う。`walk` はウォーキング・ベース（BL-086）で、根音を E2〜D#3 に置き（和音より下）、和音の中の最初の `walk` が根音（分数コードならそのベース）、間がその上へ和音の音を下から順に（分数コードでも和音の音で）、最後の `walk` が次の和音の根音の半音下（最後の和音は最初の和音へ戻る）。2 拍の和音でも、2 打目が次の和音への半音になる
- `pattern.Drums{ID, Name, Description, Meter, Hits}` — 1 小節のドラムテンプレート。拍子を必ず宣言する。`DrumHit.Note` は GM ドラムマップ（36 キック、38 スネア、42 クローズドハイハット…）
- カタログ（`pattern.Catalogue{Accompaniments, Drums}`、#207）: 伴奏の型は `internal/music/pattern/data/accompaniments.json`、ドラムの型は `data/drums.json` にあり（1 打 1 行）、`embed` で読む。拍子を省いた伴奏はどの拍子にも合い、その打の長さ 0 は小節の終わりまでを意味する。スタイルはまだ Go の表。起動時に `Catalogue.Validate` がカタログ全体の決まり（id の重複、必須の項目、拍子、打の位置と長さ、音高、強さ、声部）を一度に検査し、壊れていれば起動しない（BL-177、BL-178）。
- カタログ: 伴奏は 4/4 の `pulse` / `ballad` / `arpeggio` / `strum` / `reel`（1・3 拍にベース、各拍の裏に短い和音。スチール弦ギター）、`comp`（1・3 拍にベース、1 拍目と 2 拍目の裏に短い和音。チャールストンのリズムのジャズのコンピング）、`walking`（4 分のウォーキング・ベースと、チャールストンのリズムの短い和音。ジャズ）、3/4 の `waltz`（1 拍目にベース、2・3 拍目に和音）/ `arpeggio-3`、6/8 の `rocking-6`（拍の頭にベース、残りの 8 分 2 つに和音）/ `arpeggio-6`、どの拍子でも使える `block` と `drone`（主音と 5 度を低く保ち、その上で和音を伸ばす。声部 `drone` は和音ではなく調の主音に従う。主音を F2〜E3 に置くので 5 度も和音（C4 から上）の下に収まり、和音が替わってもつながった 1 つの音として鳴り続ける。リズムの解説は、同時に鳴る打を 1 回と数える）。ドラムは 4/4 の `eight-beat` / `ballad` / `bossa` / `bodhran`（低いタムが 1・3 拍、サイドスティックが 2・4 拍、中くらいのタムが残りの 8 分。スネアとハイハットなし）、`jazz-ride`（ライドが 1・2・2 拍の裏・3・4・4 拍の裏を刻み、足のハイハットが 2・4 拍、キックは 4 分でごく弱く。スネアなし）、3/4 の `waltz` / `jazz-waltz`（ライドが 1・2・2 拍の裏・3 拍、足のハイハットが 2 拍）、6/8 の `six-eight` / `jig`。ノリ `straight` / `swing`。`Accompaniments()` / `DrumPatterns()` / `AccompanimentsFor(ts)` / `DrumPatternsFor(ts)` / `Feels()` / `FindAccompaniment(id)` / `FindDrums(id)`。AI に見せるのは、インテントが許す拍子の型だけ
- 格子のドラム（`music.DrumGrid`、BL-122、ADR-0012 の決定 2）: 1 拍を `Division` マスに分け（4/4・3/4 では 2・3・4、6/8 では 3・6）、声部ごとに 1 小節を 1 マス 1 文字で書く。`X` は強く、`x` は普通、`o` はゴースト、`.` は休み。空白と `|` は読みやすさのためで無視する。声部は決まった語彙（`pattern.GridVoices`: kick, snare, cross-stick, hat, open-hat, pedal-hat, ride, ride-bell, crash, low-tom, mid-tom, high-tom）。`pattern.GridDrums` が、分割数・長さ・声部・文字・1 マスで要る手の数（キックとペダルのハイハットは足なので数えない。手は 2 本）・テンポで見て 100ms より短いマスを検証し、全部の問題を一度に返して、id `grid` のドラムにする。`Choice.Grid` で描画し、格子は `Rhythm.DrumGrid` に残る（BL-123。`Rhythm.Drums.ID` は `grid`）。`from-progression` は `drumGrid` を受け取り、調やスタイルを変えて作り直すときは格子を送り返す。解説は、4/4 で強いスネアかクロススティックが 2・4 拍ならバックビート、3 拍だけならハーフタイムと述べ（カタログの型でも）、格子なら鳴るマスの割合（密度）と、その拍子のカタログの型のうち打ち方（声部と位置。強さは比べない）がいちばん近いものを述べる（BL-124）。違いが 4 打までなら足した打と抜いた打を「キックを 3 拍目の裏に足し、キックを 3 拍目から抜いたもの」と名指しし、それより多ければ違う打の数だけを述べる
- スタイル（`pattern.Style`、BL-082）: ポップ・バラード・ロック・ジャズ・ボサノバ・ケルト。それぞれが合う伴奏・ドラム・ノリの一覧を持ち（ブロックの和音とドラムなしはどのスタイルでも使える）、`Misfits` が一覧の外を、合うものを添えて返す。`Styles()` / `FindStyle(id)`。型のカタログの API（`GET /patterns`）がスタイルの一覧も返し、カードはスタイルの名前を出す（BL-119）。スタイルは楽器を持てる（ケルトはハープ、ボサノバはナイロン弦ギター、ロックは歪んだギター。BL-110）。`pattern.Render` は、鍵盤を既定とする型（`arpeggio`、`block` など）をその楽器で鳴らし、型が自分の楽器を持つとき（`strum`、`reel`、`drone`）はそのままにする。描画したスタイルは `Rhythm.Style` に残り（伴奏もドラムもないブロックコードの例でも）、調を変えて作り直すときに送り返す。スタイルは拍子ごとのグルーヴ（`Style.Groove(ts)`、BL-087、ADR-0021）を持つ。その拍子のために書かれた最初の伴奏（なければどの拍子でも使える型、それもなければ `block`）、最初のドラム（なければなし）、最初のノリ（複合拍子ではスウィングを除く）で、例のスタイルを選び直すと和声はそのままでこれで作り直す。どの型もいずれかのスタイルに属する（テストで検査）。スタイルは和音の色付け（`Style.Tensions`、BL-125、ADR-0012 の決定 4）を持てる。ジャズは長七・短七・属七に 9 度、属七に 13 度、ボサノバは七の和音に 9 度、バラードは長三和音に 9 度（add9）。足すのは調の音階にある音だけで、和音の音の半音上（短 9 度）になる音は足さない。伴奏の型の `chord` 声部だけが、ボイシングの最上音より上の最も近い位置に鳴らす。ローマ数字と分析は 7 度までのまま。足した音が鳴ったときだけ `Rhythm.Style.Tensions` が何を足したかを述べる
- `pattern.Apply(tl, acc, drums)` — `Harmony` を元にトラックを作り直す。コードごとに小節単位でテンプレートを繰り返し、小節より短いコードは先頭部分だけ鳴らす。ドラムは ch.9 にタイムライン長ぶん繰り返す。4 小節ごとのフレーズの終わりの小節では、後半（3/4 と 6/8 では最後の拍）を 8 分のフィルに替え（BL-126、ADR-0012 の決定 5）、次の小節があればその頭にクラッシュを置く。フィルは型の太鼓に合わせる: キックとスネアの型はスネアからタムを高い方から低い方へ（短いフィルでも低いタムで終わる）、手で叩く太鼓（ボーラン）は中と低いタムの連打でクラッシュなし、ライドで拍を刻む型（ジャズのライド、ボサノバのライドベル）はシンバルを刻んだまま弱いスネアでつなぐ。解説はクラッシュが鳴るときだけクラッシュに触れる。4 小節に満たない例にはフィルを入れず、解説もフィルに触れない。入力は変更しない。小節の長さは拍子から決める（`music.BarTicks`）。4/4・3/4・6/8 以外、または型の拍子がタイムラインと違うときはエラー（ADR-0017）。リズムの解説は拍子の拍で拍の頭を数え（ドラムはキックとスネア、ボーランのような手で叩く太鼓なら低いタムとサイドスティックを骨格として数え、どちらもない格子（シンバルだけなど）は鳴る打をすべて数え、鳴るものだけを名指しする。スネアのない型なら「キック」）、シンコペーションは「拍の裏で鳴ったあと次の拍の頭が鳴らない」とき（Longuet-Higgins & Lee、BL-083）で、解説はどの拍の頭が鳴らないかを名指しする。裏拍の多さだけではシンコペーションにしない。`pattern.Render` は 6/8 でのスウィングを拒む（拍がすでに 3 つに分かれている）
- `pattern.Render(tl, Choice{Accompaniment, Drums, Grid, Feel, Swing, Style})` — id で選んで `Apply` し、ノリを掛ける。HTTP と `ideas` の入口。伴奏もドラムも格子もなく、スタイルが楽器も和音の色付けも持たなければ、音はそのままでスタイルだけを `Rhythm.Style` に記録して返す。ドラムだけ、または楽器か色付けを持つスタイルだけならブロックコードを使う。ドラムも押しもないブロックコードは伸ばすだけなのでスウィングを掛けない（6/8 でのスウィングはその前に拒む）
- ノリ（`Feel`）: `swing` は、組にした音価（`Swing.Unit`。既定は 8 分、16 分も選べる）の 1 つ目を長く、2 つ目を短くする。長・短の比（`Swing.Ratio`、BL-084）は 1.0（ストレート）〜3.0 で、指定がなければテンポから決まる（`DefaultSwingRatio`: 60 BPM で 3、160 で 2、速いほど浅く 1.5 まで。0.1 刻み。ジャズのドラマーで測られた傾向、Friberg & Sundström 2002）。組の中で時間を伸び縮みさせる。組の前半は長い音まで伸び、後半は短い音に縮む。そのため、組の 1 つ目の音は長くなり、2 つ目で始まる音は遅れ、2 つ目で終わる長い音（押した和音の前の和音）はそこまで伸びてつながる。2 : 1 なら 3 連符の 3 つ目。組より細かい音（8 分のスウィングでの 16 分）も、順番と間隔を保ったまま同じように動く。`Rhythm.Feel` は比と音価を持ち、解説はその比を述べる。拍の位置の分析はテンプレートの位置で行うので、スウィングしても裏拍は裏拍として数える
- 説明文（`Description`）は解説レイヤーと LLM がそのまま使う前提で、日本語で「何が起きるか」を書く
- `music.Rhythm{Accompaniment, Drums *RhythmPart, Feel *RhythmFeel}` — `Apply` が `Timeline.Rhythm` に入れる解説データ。`RhythmPart` は 1 小節の打点を拍の頭 / 8 分の裏 / それより細かい位置に分類し（ドラムは骨格の打音。上の `pattern.Apply` を参照）、拍の裏で鳴ったあと次の拍の頭が鳴らない打点があれば `Syncopated`。`Explanation` は決定論的な日本語

## 設計上の判断

- **質はスケールから導出する。** `Key.Diatonic` は三度堆積の音程から質を判定するため、モードを追加してもコードの表が不要。
- **ローマ数字の文字列は境界でだけ扱う。** 内部の分析は `degree + quality` で行い、文字列は入力（API、将来は LLM の出力）を `ParseRomanNumeral` で度数と七の和音の有無に変換するときにだけ現れる。コードの質は常に調から導出され、文字列の大文字小文字や `°` は結果に影響しない。
- **自然短音階 + 和声的短音階のドミナント。** 短調で `V` / `V7`（大文字）と書くと `StepFromLabel` が `Step.Quality` を長三和音・属七に上書きし、導音（第 7 音の半音上げ）が鳴る。根音は自然短音階上にあるので `Analyze` はそのまま度数を求め、解説に和声的短音階の一文を足す。小文字 `v` は自然短音階の短三和音。ドリアンとミクソリディアンにはこの例外がなく、`V` と書けば `CanonicalLabel` が落とす。
- **セカンダリードミナント（BL-074）。** `V/x` と `V7/x` は、度数 x の和音の 5 度上の長三和音か属七で、x を一時的な主音のように聞かせて引き寄せる（C major の `V7/V` は D7 で G へ向かう）。`Step.Applied` が立つと、`Step.Degree` は向かう先の度数を表す。向かう先は、主和音以外の長三和音か短三和音に限る（減三和音は自分のドミナントで導かれず、`V/I` は `V` そのもの）。和音が調の中にあるものは、別名にすぎないので落とす（C major の `V/IV` は主和音の C で、`V7/IV` の C7 だけがセカンダリードミナント。C minor の `V/III` は `VII`、ミクソリディアンの `V7/IV` は `I7`。長調の C7 は、`I7` と書けばブルースの属七、`V7/IV` と書けばセカンダリードミナント）。根音は、向かう先の文字の 5 度上の文字で綴る（C# minor の `V/v` は D#）。`Analyze` は、調・和声的短音階の V・借用で説明できない和音のうち、この形のものを機能 D、`AppliedTo` に向かう先の度数を入れて分析し、次の和音がその先なら「解決する」、違えば「かわす」と書く。セカンダリードミナント自体には終止を付けず、それを根音の度数として終止を読まない（V/VII から i は変格終止ではない）。ただし V/V から V に着くのは、ほかの和音から V に着くのと同じく半終止。
- **裏コード（BL-128、ADR-0023）。** `subV7/x` は、x の半音上の属七（トライトーン代理）。`V7/x` の代わりに置き、根音が三全音離れても 3 度と 7 度（三全音）は同じなので、同じように x へ引き寄せ、根音は半音上から x の根音へ降りる。C major の `subV7/I` は D♭7、`subV7/V` は A♭7。`V7/x` と違い、主和音も向かう先にできる（`subV7/I` がいちばん多い）。向かう先は長三和音か短三和音に限る。根音は向かう先の文字の 2 度上の文字で綴る（C major の `subV7/I` は C# ではなく D♭）。`Step.Applied` と `Step.Substitute` が立つ。同じ音の借用和音（C major の `bVII7` と `subV7/vi` はどちらも B♭7）はラベルで区別する。`Analyze` は機能 D、`AppliedTo` に向かう先、`Substitute` を立て、どの V7 の代わりかを名指しして、解決するか、かわすかを書く。終止は付けない（セカンダリードミナントと同じ）
- **導音の減七（BL-130、ADR-0024）。** `vii°7/x` は、x の導音（x の半音下）の上に短 3 度を重ねた減七（和音の質 `dim7`）。C major の `vii°7/ii` は C#°7、`vii°7/V` は F#°7。向かう先は主和音以外の長三和音か短三和音（`V7/x` と同じ）。根音は向かう先の文字の 2 度下の文字で綴る（C# であって D♭ ではない）。ラベルは `vii°7/x` のほか `viio7/x` も読む。`Step.Applied` と `Step.LeadingTone` が立つ。`Analyze` は機能 D、`AppliedTo`、`LeadingTone` を立て、前の和音から根音が半音で上がり、次の和音へまた半音で上がるとき（I – vii°7/ii – ii、IV – vii°7/V – V）、経過の減七（パッシング・ディミニッシュ）と述べる。終止は付けない
- **3 度のない和音（BL-132、ADR-0025）。** 和音の質 `sus4`（0・5・7）、`dom7sus4`（0・5・7・10）、`power`（0・7）。ラベルは `Vsus4`、`V7sus4`、`I5`。3 度がないので大文字で書き、小文字も受け付けて直す。和音の音がすべて調の中にある度数に置ける（C major の `IVsus4` は不可）。パワーコードは、長調で同主短調の下げた根音にも置ける（`bVII5`、`bVI5`、`bIII5`。分析は借用）。長調以外で ♭ の付いた根音が調の度数なら、その度数として読んで綴り直す（D mixolydian の `bVII5` は `VII5`）。`Analyze` は根音の度数の機能のまま、sus4 には掛留と（次の和音が同じ根音で 3 度を戻せば）解決を、パワーコードには 3 度のない響きを述べる
- **長調の借用和音（BL-094）。** 長調では、同主短調から借りた `iv`（`iv7`、`ivm6` も）、`ii°`（`iiø7`）、`bVI`（`bVImaj7`）、`bVII`（`bVII7`）を書ける。`Step.Accidental`（0 か -1）が根音を半音下げ、`Step.Borrowed` が印になる。ラベルの ♭ は `♭` でも `b` でもよく、`CanonicalLabel` が `♭` にそろえる。和音の質は同主短調のその度数と一致しなければならず（長調の `bVI7` は落ちる。`IV7` は借用ではなく下のブルースの属七）、綴りは調の文字から決める（C major の `bVI` は Ab、E major の `bVII` は D）。このセット以外の借用、その他の非ダイアトニックなコード（下のセカンダリードミナントを除く）は未対応で、`Analyze` は拒否する。
- **ブルースの属七（BL-135、ADR-0026）。** 長調では、`I7` と `IV7`（大文字で、種類を書かない `7`）を属七として書ける（C major の C7 と F7）。`Step.Quality` が属七になり、借用の印は立たない。機能は根音の度数のまま（`I7` は T、`IV7` は S）で、`Analyze` は足した 7 度を名指しして、解決を求めないブルースの属七と書く（`IV7` の 7 度は調の ♭3、ブルー・ノート）。ただし `I7` の次が調の IV なら、♭7 が IV の 3 度へ半音で下り、`V7/IV` のように IV を引き寄せて聞こえると書く（機能はトニックのまま。ADR-0034 の決定 2）。同じ C7 でも、`V7/IV` と書けばセカンダリードミナント、ラベルがなければセカンダリードミナントとして分析する。短調と旋法、ほかの度数の属七（`II7` など）は今までどおり落ちる。
- **短調の借用和音（BL-075）。** 短調では、同主長調の `I`（曲の終わりならピカルディの 3 度）と `IV`（旋律的短音階やドリアンの 6 度）、ナポリの `♭II`（主音の半音上の長三和音）を書ける。どれも三和音で、その調の音階に対して書き、音階にない根音（ナポリ）にだけ ♭ を付ける（ADR-0012 の判断 3）。機能は度数どおり（I は T、IV と ♭II は S）。C minor の C major のように、同じ和音がセカンダリードミナント（`V/iv`）にもなる場合は、ラベルで決める（`/` を含めば向かう先のある和音、なければ借用）
